### 2. 코드 수정
- 작은 단위로 수정 (파일 하나씩, 블록 단위)
- 실시간 데이터 처리 금지 목록 준수:
  - innerHTML 전체 교체 금지 → 변경된 요소만 업데이트
  - .map() 전체 재생성 금지 → 변경된 항목만 교체
  - 전체 store 초기화 후 재설정 금지 → 해당 key만 업데이트
  - setInterval() 반복 전체 조회 금지 → WS 이벤트 수신으로 대체
  - setTimeout() 중첩 재귀 금지 → 단일 이벤트 리스너로 대체
  - alert(), confirm(), prompt() 금지
  - 대용량 JSON.stringify() 금지 → delta만 직렬화

### 5. 브라우저 검증
#### 5-1. 개발 서버 실행 확인 (사실 기반 — 추정 금지)
아래 명령으로 서버 실행 여부를 실제 확인 (1초 이내). 추정이 아닌 실제 결과를 보고에 반영.
```bash
# 포트 점유 + HTTP 응답 동시 확인 (프론트엔드 5173)
lsof -ti:5173 && curl -s --connect-timeout 1 --max-time 2 http://localhost:5173 > /dev/null && echo "FRONTEND_UP" || echo "FRONTEND_DOWN"
```
- `FRONTEND_UP`: 서버 정상 응답 → 5-2 진행
- `FRONTEND_DOWN`: 서버 미응답 → 사용자에게 서버 실행 필요 안내 (SectorFlow.command 실행)

#### 5-2. 브라우저 화면 확인 (사용자 확인 항목)
에이전트는 브라우저 화면을 직접 볼 수 없으므로 사용자에게 확인 요청.
- 새로고침 후에도 정상 동작 확인
- 캐시/서비스워커 문제 없는지 확인

#### 5-3. 검증 자동화 루프(하네스) — docs/절차규칙/절차규칙_조사_상세.md 0-1-2 검증 자동화 루프 준수
정적 검증(섹션 3) + 빌드(섹션 4) 중 실패 시 통과까지 자동 반복. 상세 절차·중단 조건·0-1 관계는 docs/절차규칙/절차규칙_조사_상세.md 0-1-2 검증 자동화 루프 본문 참조. 종료 조건: `npm run typecheck` + `npm run build` + `npm run test` 전부 pass(브라우저 확인 5-2는 사용자 항목이므로 루프 종료 조건에서 제외). 섹션 8 보고에 루프 결과 명시.

### 6. UI 문제 확인 순서
#### 버튼/입력값이 동작하지 않는 문제
1. 이벤트 핸들러가 연결되어 있는가
2. 핸들러가 호출되는가
3. store/state가 변경되는가
4. 변경된 state가 다시 UI에 반영되는가
5. 타입 오류나 값 변환 문제가 있는가

#### 화면이 예전 상태로 보이는 문제
1. 개발 서버가 최신 번들을 제공하는가
2. 브라우저 강력 새로고침을 했는가
3. 서비스워커가 등록되어 있는가
4. 캐시가 남아 있는가

## 주의사항
- 빌드 성공만으로 브라우저 표시가 100% 보장되는 것은 아님
- UI 문제는 실제 화면 확인 필요
- 실시간 수신 데이터는 delta만 처리, 50ms 초과 시 경고 로그, 200ms 초과 시 처리 중단 및 원인 보고
- **P21 (사용자 투명성)**: 백엔드 상태(매수 차단, 리스크 초과 등)를 UI에 표시하지 않으면 사용자가 원인을 알 수 없음 — 새 기능 추가 시 백엔드 상태 표시 여부 확인
- **P23 (용어 통일)**: UI 텍스트에 용어 사전(`ARCHITECTURE.md` 부록 B) 준수 — "업종" not "섹터", "종목" not "주식", "매수 후보" not "바이 리스트"
