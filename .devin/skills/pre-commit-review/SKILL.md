## 역할

작업을 마친 뒤, 커밋하기 전에 **방금 바뀐 부분만 모아 점검**하는 읽기 전용 절차.
기계 검증(문법·테스트·린트 통과)이 "돌아가는가"를 본다면, 이 스킬은 "바뀐 내용이 안전하고 의도에 맞는가"를 본다. 역할 보완이지 중복이 아님.

> **읽기 전용 명시**: 본 스킬은 코드를 수정하지 않는다. 판정만 출력하고, 수정은 원래 작업 세션에서 수행한다.
> **실행 도구 제한**: `exec`는 `git diff`, `git log`, `git show`, `git status` 계열 명령만 사용한다. 코드 변경·커밋·푸시 명령은 금지.

## 사용자 전제 (필수)
> **공통 전제 (승인 전 수정 금지·사용자 소통·보고·오류 알림 의무·작업 시작 전 아키텍처 판정 필수·완료 보고 봉인)**: problem-solve 스킬 "사용자 전제" 섹션 (.devin/skills/problem-solve/SKILL.md) 참조. 단, 본 스킬은 읽기 전용이므로 "승인 전 수정 금지"는 자동 충족(수정 도구 없음).

## 절차

### 1. 변경 내역 수집
- `git status` — 변경된 파일 목록 확인
- `git diff` — 작업 디렉터리 변경 내용 확인 (스테이징 전·후 모두)
- `git log -p -1` 또는 `git show <커밋>` — 이미 커밋된 변경 검토 시
- 변경 범위가 크면 파일별로 나누어 검토

### 2. 점검 항목

#### 2-1. 논리 오류·빠진 오류 처리·되돌려야 할 위험 변경
- 분기가 빠진 경우, 예외를 무시한 catch, 반환값 미사용
- 안전 규칙 위반 변경 (DB 파일 삭제·덮어쓰기, 매매 코드 테스트 모드 해제 등)
- 되돌려야 할 위험 변경이 있는지 — 있다면 "커밋하면 안 됨" 후보

#### 2-2. 의도와 일치 여부 (역할: 범위 초과 점검 — 중복 원장 #2)
- **"요청 안 한 변경이 섞였나?"** (범위 초과 점검)
- 요청하지 않은 변경이 섞여 있지 않은가 (범위 초과)
- 설계서·태스크 파일의 완료 기준과 일치하는가
- **역할 분리**: "내가 요청받은 대로 만들었나?"(작성자 자기 점검)는 세션절차 상세 1단계, "작성자가 놓친 요청-구현 불일치가 있나?"(독립 검증)는 independent-verify 스킬이 담당. 본 스킬은 커밋 전 범위 초과 점검에 집중.

#### 2-3. 다른 부분에 미치는 영향 (회귀 위험)
- 같은 함수·변수·상태를 참조하는 다른 코드가 깨지지 않는가
- 공통 컴포넌트·공통 함수 변경 시 호출처 전수 확인
- 프론트엔드 상태·백엔드 SSOT 위치 변경 시 연동 지점 점검

#### 2-4. 거래 로직 변경 시 (safe-trade와 연계)
- 거래·매매·주문·리스크 로직이 포함된 경우에만 적용
- 손실 시나리오 영향 — 잘못된 경로로 실전 주문이 나가지 않는가
- 테스트 모드/실전 모드 분기가 올바른가
- 단일 주문 경로(P15)를 우회하는 분기가 새로 생기지 않았는가
- 상세는 safe-trade 스킬 (.devin/skills/safe-trade/SKILL.md) 참조

### 3. 판정 출력 (세 가지 중 하나 + 근거)

| 판정 | 조건 | 후속 |
|---|---|---|
| **커밋해도 됨** | 4개 점검 항목 모두 문제 없음 | 원래 작업 세션에서 커밋 진행 |
| **고치고 커밋** | 일부 항목 수정 필요 — 수정 항목 명시 | 원래 작업 세션에서 수정 후 재검토 |
| **커밋하면 안 됨** | 위험 변경 포함 — 사유 명시 | 변경을 되돌리거나 사용자 승인 필요 |

판정 시 근거를 일반 사용자 용어로 작성 (규칙 0-8 1항). 파일 경로·줄번호·함수명은 사용자 보고 본문에 노출 금지.

### 4. 완료 보고
> **사용자 보고 의무**: docs/절차규칙/절차규칙_조사_상세.md 규칙 0-8 준수 (UI 기준 일반 용어). 보고서 형식은 docs/절차규칙/절차규칙_보고_상세.md '작업 완료 보고서 표준 형식' 참조.

- **변경 내용 표**: 검토한 변경 범위(파일 수·주요 영역)
- **검증 결과 표**: 4개 점검 항목별 통과/수정 필요/위험 여부
- **최종 판별 표**: 세 가지 판정 중 하나 + 근거 요약
- 거래 로직 포함 시 손실 시나리오 점검 결과 별도 표시

### 5. 증거 파일 저장 (강제 — 하네스 강화)
검토 완료 후 판정 결과를 증거 파일로 저장 — 완료 전 검사 스크립트가 이 파일 존재를 확인하여 실행 여부를 기계적으로 판정.

- **저장 경로**: `.devin/state/verify-results/pre-commit-review-<커밋해시또는날짜>.md`
- **파일 내용**: 판정(커밋해도 됨/고치고 커밋/커밋하면 안 됨) + 4개 항목별 결과 + 근거 요약
- **목적**: "에이전트가 알아서 따라야 하는 절차"에서 "안 하면 진행 불가" 방식으로 전환. 파일이 없으면 완료 전 검사 스크립트가 완료 보고를 차단. 패턴: Evidence before claims(OpenAI superpowers) — 검증 없이 완료 주장 불가.
