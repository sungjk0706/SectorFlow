## 역할

작업 완료 후, 작업을 수행한 본인이 아닌 **별도 작업창(서브에이전트)에서 같은 변경을 다시 검토**하여 놓친 점을 찾는 읽기 전용 절차.
기계 검증(문법·테스트·린트 통과)이 "돌아가는가"를, pre-commit-review가 "바뀐 내용이 안전하고 의도에 맞는가"를 본다면, 본 스킬은 **"작성자가 아닌 독립된 시선"**으로 같은 질문을 다시 묻는다. 역할 보완이지 중복이 아님.

> **독립성 명시 (핵심)**: 본 스킬은 `subagent: true`로 별도 작업창에서 실행된다 — 작업을 수행한 세션의 컨텍스트를 물려받지 않고, 변경 내역·설계서·태스크 파일만 보고 판정한다. 작성자=검증자 편향을 기술적으로 차단하는 것이 본 스킬의 존재 이유.
> **읽기 전용 명시**: 본 스킬은 코드를 수정하지 않는다. 판정만 출력하고, 수정은 원래 작업 세션에서 수행한다.
> **실행 도구 제한**: `exec`는 `git diff`, `git log`, `git show`, `git status` 계열 명령만 사용한다. 코드 변경·커밋·푸시·설정 변경 명령은 금지.

## 사용자 전제 (필수)
> **공통 전제 (승인 전 수정 금지·사용자 소통·보고·오류 알림 의무·작업 시작 전 아키텍처 판정 필수·완료 보고 봉인)**: problem-solve 스킬 "사용자 전제" 섹션 (.devin/skills/problem-solve/SKILL.md) 참조. 단, 본 스킬은 읽기 전용이므로 "승인 전 수정 금지"는 자동 충족(수정 도구 없음).

## 적용 계층 (위험도에 따라 — P24 단순성)

| 위험도 | 대상 | 적용 |
|---|---|---|
| **낮음** | 1파일 오타·문서 수정·주석 변경 등 | 생략 가능 (사전조사 시 "회귀 위험 없음" 명시한 경우) |
| **중간** | 일반 기능 수정·다수 파일 변경·공통 자산 변경 | 권장 |
| **높음** | 거래·매매·주문·리스크·핵심 로직 변경 | **필수** (생략 불가) |

모든 변경에 필수 적용하면 P24(단순성) 위반이므로 위험도 계층화를 반드시 따른다.

## 점검 항목 (4개)

### 1. 설계서 완료 기준이 모두 충족되었는가
- 설계서 "완료 기준"(사용자 관점 달성 항목)을 한 항목씩 대조 — 문서 역할 원칙 "검증=설계 완료기준 따른다" 준수
- 태스크 파일의 완료 조건(Done Criteria)과 실제 구현이 일치하는가
- "완료"로 표시된 체크박스가 기계적 검증 결과(명령어 통과)에 기반했는지, 자기 평가로 끝나지 않았는가

### 2. 요청 의도와 실제 구현이 일치하는가
- 사용자 원래 요청 내용을 다시 읽고, 변경 내역이 그 요청을 해결하는가
- 요청하지 않은 변경이 섞여 있지 않은가 (범위 초과 점검)
- "비목표"로 명시된 것을 건드리지 않았는가

### 3. 태스크에 없는 로직/분기/상태가 추가되지 않았는가 (설계 이탈 점검)
- 태스크 파일에 적힌 수정 범위를 벗어나는 코드가 새로 들어갔는가
- 설계서에 없는 분기·상태·필드가 임의로 추가되지 않았는가
- "요청하지 않은 개선"이 구현에 끼어들지 않았는가

### 4. 거래·핵심 로직 변경 시: 손실 시나리오·회귀 위험 독립 확인
- 거래·매매·주문·리스크 로직이 포함된 경우에만 적용 (위험도 높음 → 필수)
- safe-trade 스킬의 Pre-mortem 정량 손실 시나리오 대비 안전한가
- 단일 주문 경로(P15)를 우회하는 분기가 새로 생기지 않았는가
- 테스트 모드/실전 모드 분기가 올바른가 (P18 동등성)
- 상세는 safe-trade 스킬 (.devin/skills/safe-trade/SKILL.md) 참조

## 판정 출력 (충족/미충족 + 근거)

| 판정 | 조건 | 후속 |
|---|---|---|
| **충족** | 4개 점검 항목 모두 문제 없음 | 원래 작업 세션에서 완료 보고 진행 |
| **미충족** | 일부 항목에서 문제 발견 — 미충족 항목 + 근거 명시 | **"중단·보류" 권고** — 원래 작업 세션에서 수정 후 재검증 |

판정 시 근거를 일반 사용자 용어로 작성 (규칙 0-8 1항). 파일 경로·줄번호·함수명은 사용자 보고 본문에 노출 금지.
미충족 항목이 거래·핵심 로직 관련이면 즉시 사용자 알림 (규칙 0-9 — 오류·위험 즉시 알림).
