## 역할

코드베이스 전체를 대상으로 **정기적으로 보안 상태를 점검**하는 읽기 전용 절차.
커밋 직전의 좁은 범위 검토는 pre-commit-review가, 매매 로직 수정 시점의 안전성 검사는 safe-trade가 담당한다면, 본 스킬은 **정기 점검·실전 모드 전환 전**처럼 시점이 정해진 넓은 범위 순찰을 담당한다. 역할 보완이지 중복이 아님.

> **읽기 전용 명시**: 본 스킬은 코드를 수정하지 않는다. 발견된 위험만 보고하고, 수정은 별도 작업 세션에서 수행한다.
> **실행 도구 제한**: `exec`는 `grep` 계열 탐색 명령만 사용한다. 코드 변경·설정 변경·외부 스크립트 실행 명령은 금지.
> **safe-trade와의 분리**: safe-trade는 "매매 로직 수정 시" 즉시 적용, 본 스킬은 "정기 점검·실전 모드 전환 전"처럼 시점이 정해진 넓은 범위 점검에 적용. 두 스킬은 시점·범위가 다르므로 함께 사용해도 중복 아님.

## 사용자 전제 (필수)
> **공통 전제 (승인 전 수정 금지·사용자 소통·보고·오류 알림 의무·작업 시작 전 아키텍처 판정 필수·완료 보고 봉인)**: problem-solve 스킬 "사용자 전제" 섹션 (.devin/skills/problem-solve/SKILL.md) 참조. 단, 본 스킬은 읽기 전용이므로 "승인 전 수정 금지"는 자동 충족(수정 도구 없음).

## 점검 시점

- **정기 점검**: 사용자가 주기적으로 요청할 때 (예: 월 1회, 큰 변경 직후)
- **실전 모드 전환 전**: 테스트 모드에서 실전 모드로 전환하기 전 필수 — 전환 승인 전 본 점검 통과가 전제
- **큰 변경 이후**: 거래 로직·인증·설정 구조 등 보안 민감 영역 대폭 변경 후

## 점검 항목 (5개)

### 1. 증권사 접속 열쇠·비밀번호·계좌 번호 노출
- 코드에 API 키·토큰·비밀번호·계좌 번호가 직접 적혀 있는지 전수 검색
- 환경 변수·설정 저장소 외 경로에 하드코딩된 값이 있는지
- 로그·에러 메시지에 열쇠·비밀번호가 평문으로 찍히지 않는지
- AGENTS.md 안전 규칙 4(증권사 API 키 하드코딩 금지) 준수 여부

### 2. 위험 명령 실행 경로 노출
- `sudo`, `rm -rf`, 외부 스크립트 실행(`curl`/`wget` 파이프 실행 등)이 무방비로 코드에 들어있는지
- 사용자 승인 없이 실행되는 위험 명령 경로가 있는지
- AGENTS.md 안전 규칙 5(`sudo`/`rm -rf`/`curl`/`wget`/`sqlite3` 승인 없이 실행 금지) 준수 여부

### 3. 외부 입력 검증 부재
- 외부 입력(웹 요청·웹소켓 메시지·증권사 응답·파일 입력)이 검증 없이 내부 로직으로 흘러들어가는지
- SQL 조립·명령어 조립·경로 조립에 외부 입력이 그대로 사용되는지
- 수치형·문자열 입력의 범위·형식 검증이 빠진 지점이 있는지

### 4. 설정 파일 저장소 노출
- `.env`·비밀 키 파일·인증 파일이 저장소에 들어가 있는지
- `.gitignore`가 보안 민감 파일을 올바르게 제외하고 있는지
- 백업 파일·임시 파일에 열쇠·비밀번호가 남아있지 않은지

### 5. 거래 로직 접근 통제 (실전/테스트 모드 전환 보호)
- 실전 모드 전환이 올바른 승인 절차(AGENTS.md 안전 규칙 3 — 3가지 인지 후 승인)를 거치는지
- 테스트 모드 안전장치가 우회 가능한 경로로 존재하지 않는지
- 단일 주문 경로(P15) 외에 실전 주문이 나갈 수 있는 숨은 경로가 없는지
- 실전/테스트 모드 분기가 돈 I/O 최소 지점 외에 불필요하게 추가되어 있지 않은지

## 판정 출력 (심각도별 + 권장 조치)

| 심각도 | 조건 | 권장 조치 |
|---|---|---|
| **높음** | 실전 열쇠 노출·실전 주문 우회 경로·테스트 모드 안전장치 우회 가능·저장소에 평문 열쇠 | 즉시 수정 필요 — 실전 모드 전환 금지, 사용자에게 즉시 알림 |
| **중간** | 외부 입력 검증 부재·위험 명령 무방비 노출·로그에 민감 정보 일부 노출 | 사용자에게 보고 후 별도 작업 세션에서 수정 |
| **낮음** | 예외적 상황에서만 위험 가능·권장 사례 미준수 | 정기 점검 보고에 기록, 다음 정기 점검 시 재확인 |

판정 시 근거를 일반 사용자 용어로 작성 (규칙 0-8 1항). 파일 경로·줄번호·함수명은 사용자 보고 본문에 노출 금지.
