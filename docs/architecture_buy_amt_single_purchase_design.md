## 1. 배경 및 목표

### 1.1 현재 상태 (기존 구조/문제)

매수 설정에 두 가지 설정이 존재하며 역할이 겹치고 해석이 불일치함.

**설정 1 — 재매수 차단** (`rebuy_block_on` + `rebuy_block_period`):
- `trading.py` 344-359줄 — 오늘 매수한 종목(`_bought_today`)이면 무조건 차단.
- 기준: **횟수** (1회 매수 → 차단).
- 단위: "today" 또는 "Nh".

**설정 2 — 종목당 일일 한도** (`buy_amt_on` + `buy_amt`):
- UI(`buy-settings.ts` 351줄) 라벨: "종목당 일일 한도" — 누적 금액 한도 의도.
- `trading.py` 389-411줄 — `_symbol_daily_buy_spent`(종목당 오늘 누적 매수금액)와 `buy_amt` 비교 → 잔여만큼 주문. **누적 한도 해석**.
- `buy_order_executor.py` 132-164줄 — `buy_amt` 전체를 `effective_buy_amt`로 사용, 누적 고려 없음. **1회 매수금액 해석**.

**핵심 문제 (P10 SSOT 위반)**:
`buy_amt`가 두 백엔드 파일에서 다르게 해석됨.
- 첫 매수: 두 해석이 같음(`buy_amt` 전체).
- 재매수 차단 OFF + 같은 종목 재매수 시도:
  - `buy_order_executor`는 `buy_amt` 전체를 매수 후보 판정 기준으로 사용.
  - `trading.py`는 누적 한도 잔여만큼만 실제 주문 금액으로 산정.
- 결과: 사용자가 "재매수 차단 OFF"로 설정해도 `trading.py`의 누적 한도가 사실상 재매수를 금액 제한 — **사용자가 "재매수 차단을 껐는데 왜 안 사지?"라고 느낄 수 있음** (P21 사용자 투명성 위반 소지).

**사용자 진단**:
> "매수설정에 종목당 일일 한도, 재매수 차단 설정이 충돌이 있어 보인다. 재매수 차단 OFF 시에도 종목당 일일 한도가 있으면 재매수 차단 ON의 효과 아닐까? 종목당 일일 한도가 종목당 1회 한도로 변경해야 하나."

### 1.2 목표 (사용자 관점)

1. **역할 분리** — `buy_amt`를 "종목당 1회 매수금액"으로 단일화. 한 번 매수 시 이 금액만큼 매수.
2. **재매수 차단이 횟수 담당** — 같은 종목 재매수 허용/차단은 오직 `rebuy_block_on` 설정만 담당.
3. **두 설정이 겹치지 않음** — 재매수 차단 OFF + 종목당 1회 매수금액 ON이면, 잔고가 허용하는 한 같은 종목을 `buy_amt`만큼 반복 매수 가능.
4. **P10 SSOT 회복** — `buy_amt` 해석이 `trading.py`와 `buy_order_executor.py`에서 동일(1회 매수금액).

### 1.3 비목표 (다루지 않는 것)

- `rebuy_block_on`/`rebuy_block_period` 설정 자체의 동작 변경 없음 — 횟수 기반 차단 그대로 유지.
- `max_daily_total_buy_amt`(전체 일일 한도) 설정 변경 없음 — 전체 일일 누적 한도는 그대로.
- `max_stock_cnt`(최대 보유 종목수) 변경 없음.
- `buy_amt` 설정 키 이름 변경 없음 — 코드 호환성 유지, **UI 텍스트와 주석만 "1회 매수금액"으로 변경** (설정 키 `buy_amt`는 그대로).
- 매수 주문 경로(`execute_buy()` 단일 경로, P15) 변경 없음 — 경로 내부 금액 계산 로직만 수정.
- 매도 로직 변경 없음.

## 2. 설계 방향

### 2.1 핵심 설계 결정

**결정 1: `buy_amt` 의미를 "종목당 1회 매수금액"으로 단일화**
- 왜: 두 설정의 역할 중복 제거 + P10 SSOT 회복. `buy_amt`는 "한 번에 매수할 금액"만 담당, 재매수 횟수는 `rebuy_block_on`이 담당.
- 변경:
  - `trading.py` 389-411줄 — `_symbol_daily_buy_spent` 누적 한도 비교 로직 제거. `effective_buy_amt = buy_amt`(매번 전체). `max_daily_total_buy_amt`와의 min 계산은 유지(전체 일일 한도는 별개 설정).
  - `buy_order_executor.py` 132-164줄 — 이미 `buy_amt` 전체 기반이므로 로직 변경 없음(해석 일치화로 자연 해결).

**결정 2: `_symbol_daily_buy_spent` 상태 제거**
- 왜: 누적 한도 로직 제거로 더 이상 필요 없음. P16(살아있는 경로) — 호출되지 않는 상태 유지 금지.
- 변경:
  - `trading.py` 245줄 — `_symbol_daily_buy_spent` 인스턴스 변수 제거.
  - `trading.py` 249-272줄 `_load_daily_buy_state` — `symbol_spent` 로드 부분 제거. `_bought_today`(재매수 차단용)와 `_daily_buy_spent`(전체 일일 한도용)는 유지.
  - 반환 시그니처: `(spent, bought_today)` 2-tuple으로 축소.

**결정 3: `BUY_REJECT_SYMBOL_LIMIT` 상수 제거**
- 왜: 누적 한도 도달 차단이 더 이상 발생하지 않음. P16 — 도달 불가능한 차단 코드 유지 금지.
- 변경:
  - `trading.py` — `BUY_REJECT_SYMBOL_LIMIT` 상수 정의 제거 + `BUY_REJECT_REASON_TEXT` 매핑 제거.
  - 관련 테스트 제거/수정 (2세션 태스크 파일에서 상세).

**결정 4: UI 텍스트 "종목당 일일 한도" → "종목당 1회 매수금액"**
- 왜: P21(사용자 투명성) + P23(용어 일치) — 설정의 실제 동작과 UI 라벨 일치.
- 변경:
  - `buy-settings.ts` 351줄 라벨: "종목당 일일 한도" → "종목당 1회 매수금액".
  - `buy-settings.ts` 352줄 infoText: "종목당 하루 매수 금액 제한..." → "1회 매수 시 금액. 같은 종목 재매수는 '재매수 차단' 설정이 담당."
  - `buy-settings.ts` 318줄 infoText(전체 일일 한도) — "종목당 한도가 우선 적용" 표현이 더 이상 맞지 않으므로 "전체 일일 누적 한도. 수수료 포함. OFF 시 제한 없음."으로 정리.

**결정 5: 설정 키 `buy_amt`/`buy_amt_on` 이름 유지**
- 왜: P24(단순성) — 설정 키 rename은 DB 저장값·프론트 타입·API·테스트 전면 수정을 유발하나 의미 변경만으로 목표 달성 가능. 코드 호환성 유지.
- 변경: 설정 키 이름 그대로, 주석과 UI 텍스트만 "1회 매수금액"으로 갱신.

### 2.2 기각 방안

| 방안 | 기각 사유 |
|------|-----------|
| B. 현재 구조 유지 + UI 안내만 | 근본 문제(P10 SSOT 위반, 두 파일 해석 불일치) 해결 안 함. 안내만으로는 `trading.py`의 누적 한도 동작이 그대로라 사용자 혼란 원인 잔존. |
| C. 재매수 차단 제거 + 종목당 일일 한도로 통일 | 금액 기반이라 부분 체결 시 재매수 허용되어 "1회 차단" 의도 불가. 사용자가 원한 "재매수 차단 OFF 시 여러 번 매수 허용" 유연성 상실. |
| 설정 키 `buy_amt` → `buy_amt_per_order` rename | 의미 변경만으로 목표 달성 가능. rename은 DB 마이그레이션·프론트 타입·API·테스트 전면 수정 유발 (P24 단순성 위반). |

## 3. 사용자 결정 항목

> problem-solve 섹션 1-1 의무 기록. 2세션 태스크 파일에서 활용.

**질문 1: 두 설정의 역할을 어떻게 정리할까?**
- 사용자 선택: **A. 역할 분리 (추천)** — `buy_amt`를 '종목당 1회 매수금액'으로 변경, 재매수 차단이 횟수 담당.
- 사유: 두 설정이 겹치지 않고 각자 명확한 역할. 재매수 차단 OFF면 같은 종목 여러 번 매수 허용, 매번 `buy_amt`만큼 매수.

**질문 2: 진행 방식**
- 사용자 선택: **다단계 워크플로우** — 설계 → 태스크 → 구현 3세션 진행.
- 사유: 거래 로직 변경 영향 범위를 문서로 먼저 확정 후 단계적 구현. 안전성 최우선.

**사전조사로 확정된 항목 (질문 생략 — 규칙 0-2-6)**:
- `buy_amt` 기본값 100만원 유지 — 설정값이며 사용자가 UI에서 조정 가능.
- `BUY_REJECT_SYMBOL_LIMIT` 제거 — 누적 한도 로직 제거로 도달 불가 (P16).
- 설정 키 이름 유지 — rename 비용 > 이익 (P24).
- 실전/모의 전환 없음 — 본 변경은 모드 무관 공식 변경.

## 5. 위험도 산정

**위험도: 높음**

근거: 거래 로직(매수 주문 금액 계산) 변경. `execute_buy()` 주문 금액 산정 경로 수정(P15 단일 주문 경로 내부). 실전 모드에서 실제 주문 금액이 달라질 수 있음.

**비개발자용 3줄 요약**:
- **문제**: 현재 '종목당 일일 한도' 설정이 '재매수 차단' 설정과 겹쳐서, 재매수 차단을 꺼도 한도 때문에 같은 종목을 다시 안 사는 현상 발생. 같은 설정이 두 군데서 다르게 해석됨.
- **해결**: '종목당 일일 한도'를 '종목당 1회 매수금액'으로 바꾸고, 같은 종목 재매수 허용/차단은 오직 '재매수 차단' 설정만 담당하도록 역할 분리.
- **위험도**: 높음 — 실제 매수 주문 금액 계산 로직이 바뀌므로, 모의투자에서 먼저 확인 후 실전 적용 필요.

- (a) 롤백 명령: `git revert <구현 커밋 해시>` (2세션 태스크 파일에 해시 기재).
- (b) 즉시 롤백 트리거 증상:

### 모의 관찰 기준 (검증·관찰 계층 게이트 — 위험도 높음)
- 모의투자(dry_run)에서 관찰:
  - 재매수 차단 OFF + 같은 종목 신호 2회 → 2회 모두 `buy_amt`만큼 매수되는지 확인.
  - 재매수 차단 ON + 같은 종목 신호 2회 → 1회만 매수되는지 확인.
  - 전체 일일 한도 도달 시 매수 차단되는지 확인.
- 사용자 직접 확인 항목: 텔레그램 알림의 매수 금액 ↔ 프론트 화면 매수 후보 금액 일치.
