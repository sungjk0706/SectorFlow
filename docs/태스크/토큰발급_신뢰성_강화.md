- [x] **2-1. `auth_utils.py` 신규 파일 생성** — `backend/app/core/auth_utils.py` 생성. import: `random`, `asyncio`, `constants.py`의 TOKEN_* 상수. 모듈 docstring에 "토큰 발급 전용 공통 함수 — 적용 범위: 토큰 발급·재발급·회복 루프 (범용 라이브러리 아님, P24)" 명시.
- [x] **2-2. `compute_backoff_delay` 함수 구현** — 지수 백오프+풀 지터 대기 시간 계산:
  - 시그니처: `def compute_backoff_delay(attempt: int, base: float = TOKEN_BACKOFF_BASE_SEC, jitter_ratio: float = TOKEN_BACKOFF_JITTER_RATIO) -> float`
  - 구현: `base_delay = base * (2 ** attempt)` → `return random.uniform(0, base_delay * jitter_ratio)` (풀 지터)
  - 429 시에도 동일 함수 사용 — 호출부에서 attempt를 그대로 전달하면 429 전용 간격 분기는 제거 가능 (429는 일시 실패 코드 집합에 포함)
- [x] **2-3. `classify_token_failure` 함수 구현** — 실패 분류 판정 (결정 6 기준):
  - 시그니처: `def classify_token_failure(status_code: int | None, exception: Exception | None = None, response_text: str = "", permanent_keywords: frozenset = TOKEN_PERMANENT_RESPONSE_KEYWORDS) -> str`
  - 반환: `"permanent"` / `"transient"` / `"success"` (status_code 200 + 예외 없음 시)
  - 판정 순서: (1) exception 존재 + 네트워크 계열(DNS·연결 거부·타임아웃) → `"transient"` (2) status_code in `TOKEN_PERMANENT_HTTP_CODES` → `"permanent"` (3) status_code in `TOKEN_TRANSIENT_HTTP_CODES` → `"transient"` (4) response_text에 permanent_keywords 포함 → `"permanent"` (5) 기타 예외 → `"transient"` (안전 쪽: 일시 실패로 분류하여 회복 루프 진입)
- [x] **2-4. `retry_once_on_401` 헬퍼 함수 구현** — 401 감지 시 재발급 후 1회 재시도 패턴 (결정 3):
  - 시그니처: `async def retry_once_on_401(issue_token_fn, request_fn, *, on_reissue_success=None) -> tuple` — `issue_token_fn`은 토큰 재발급 coroutine, `request_fn`은 원 요청 coroutine(재발급 후 재시도), `on_reissue_success`는 재발급 성공 시 헤더 갱신 등 콜백
  - 구현: 첫 요청 → 401 시 `issue_token_fn()` 호출 → 성공 시 `on_reissue_success()` 콜백(헤더 갱신) → `request_fn()` 1회 재시도 → 결과 반환. 재발급 실패 시 원 실패 응답 반환. 1회만 재시도 — 무한 루프 방지 (P24).
  - 키움 `_call_api`·LS `_place_order` 양쪽에서 동일 헬퍼 호출 — 중복 패턴 제거 (결정 7)
- [x] **2-5. `should_continue_recovery` 헬퍼 함수 구현** — 회복 루프 계속 여부 판정:
  - 시그니처: `def should_continue_recovery(attempt: int, max_attempts: int = TOKEN_RECOVERY_MAX_ATTEMPTS) -> bool`
  - 구현: `return attempt < max_attempts`
  - 회복 루프(5세션)에서 호출 — 10회 상한 판정을 공통 함수로 단일화
