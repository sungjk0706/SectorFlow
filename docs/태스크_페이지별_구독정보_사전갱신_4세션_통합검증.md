# 태스크: 페이지별 구독 대상 사전 갱신 — 4세션 통합 검증

- **문서 역할**: 구현 완료 여부와 회귀 검증 기준 정의
- **세션**: 4/4
- **상태**: 1~3세션 완료 후 수행
- **선행 조건**: 백엔드 대상 관리·전달·프론트엔드 전환 완료
- **작업 결과**: 검증 통과 시 사용자 화면 확인 권유 후 작업 종료

## 1. 검증 목표

여덟 페이지가 페이지 이름만으로 최신 서버 자료에 연결되고, 원본 변경 시 화면별 대상 구독 또는 자료 스냅샷이 함께 갱신되는지 확인한다.

## 2. 기계적 검증

- [ ] 변경된 백엔드 테스트를 먼저 실행한다.
- [ ] 변경된 프론트엔드 테스트를 먼저 실행한다.
- [ ] 백엔드 전체 테스트를 실행한다.
- [ ] 프론트엔드 전체 타입 검사를 실행한다.
- [ ] 프론트엔드 전체 린트를 실행한다.
- [ ] 프론트엔드 전체 빌드를 실행한다.
- [ ] 프론트엔드 전체 테스트를 실행한다.
- [ ] 런타임 경고를 오류로 취급한 앱 기동 검사를 실행한다.
- [ ] 완료 전 표준 사전 완료 검증 스크립트를 실행한다.
- [ ] 검증 실패 시 원인을 해결한 뒤 해당 검증을 다시 실행한다.

## 3. 서버 동작 시나리오

### 3.1 업종 순위

- [ ] 화면 활성화 시 코드 목록 없이도 현재 필터 통과 종목이 등록된다.
- [ ] 초기 스냅샷에 확정 데이터와 초기 시세가 함께 들어온다.
- [ ] 설정 변경으로 최소 거래대금 기준을 바꾸면 대상이 갱신된다.
- [ ] 장 마감 후 5일 평균 거래대금이 갱신되면 대상이 갱신된다.
- [ ] 시장 시간대 변경 시 대상 정책이 기존 계약과 일치한다.
- [ ] 대상에서 빠진 종목은 더 이상 실시간 변경분을 받지 않는다.
- [ ] 새로 들어온 종목은 초기 스냅샷을 받는다.

### 3.2 매수 후보

- [ ] 후보 목록이 바뀌면 대상 구독이 갱신된다.
- [ ] 새 후보가 초기 스냅샷을 받는다.
- [ ] 탈락 후보가 더 이상 실시간 변경분을 받지 않는다.
- [ ] 후보가 없는 상태에서 기존 대상이 정리된다.

### 3.3 보유 종목·수익 현황

- [ ] 신규 매수 후 두 화면에 새 종목이 추가된다.
- [ ] 부분 매도 후 종목이 유지되고 수량·가격 표시가 정상이다.
- [ ] 전량 매도 후 두 화면에서 대상이 제거된다.
- [ ] 보유 종목이 없는 상태에서 빈 화면이 정상 표시된다.

### 3.4 수익 상세·종목 분류·종목 상세·일반 설정

- [ ] 수익 상세 화면이 이력 초기 스냅샷을 받는다.
- [ ] 매수·매도 이력 추가·변경이 수익 상세 화면에 반영된다.
- [ ] 종목 분류 화면이 분류 초기 스냅샷을 받는다.
- [ ] 분류 변경이 종목 분류 화면에 반영된다.
- [ ] 종목 상세 화면이 5일 일봉 초기 스냅샷을 받는다.
- [ ] 장 마감 일봉 갱신이 종목 상세 화면에 반영된다.
- [ ] 일반 설정 화면이 마스킹된 설정 초기 스냅샷을 받는다.
- [ ] 설정 변경이 일반 설정 화면에 반영된다.
- [ ] 네 화면 모두 종목 실시간 구독을 불필요하게 등록하지 않는다.

### 3.5 재연결·페이지 전환

- [ ] 재연결 시 페이지 이름만으로 최신 대상이 복구된다.
- [ ] 재연결 중 이전 페이지 대상이 남지 않는다.
- [ ] 업종 순위에서 매수 후보로 이동하면 업종 대상이 정리되고 후보 대상이 등록된다.
- [ ] 보유 종목과 수익 현황이 같은 보유 대상 집합을 사용한다.
- [ ] 동일 종목을 여러 연결이 사용하는 경우 각 연결이 초기 스냅샷을 빠짐없이 받는다.

## 4. 원칙 검증

### 단일 관리 원칙 (P10)

- [ ] 페이지별 구독 대상의 원본이 하나로 정해져 있다.
- [ ] 프론트엔드가 대상 목록을 별도로 유지하지 않는다.
- [ ] 보유 종목과 수익 현황이 별도 보유 코드 복사본을 만들지 않는다.
- [ ] 초기 스냅샷·변경분·화면 표시가 같은 마스터 자료를 사용한다.

### 이벤트 기반 갱신 원칙 (P11)

- [ ] 설정·확정 데이터·시장 시간대·후보·보유·재연결 이벤트가 갱신을 호출한다.
- [ ] 일정 시간마다 반복 확인하는 로직이 없다.
- [ ] 실시간 틱마다 전체 대상 목록을 다시 만드는 로직이 없다.

### 단순성 원칙 (P24)

- [ ] 대상 계산 로직이 페이지마다 중복되지 않는다.
- [ ] 대상 저장소와 연결별 전달 상태의 역할이 분리되어 있다.
- [ ] 변경이 없을 때 불필요한 재등록·전체 스냅샷이 없다.
- [ ] 화면 이름과 대상 종류의 연결이 한 곳에서 확인된다.

## 5. 회귀 확인

- [ ] 매매 판단 결과가 수정 전과 동일하다.
- [ ] 주문 실행 경로가 수정되지 않았다.
- [ ] 매도 조건이 수정되지 않았다.
- [ ] 업종 점수 계산식이 수정되지 않았다.
- [ ] 계좌 요약과 거래 내역 화면이 정상이다.
- [ ] 실시간 현재가·등락·거래대금·체결강도가 정상 갱신된다.
- [ ] 5일 평균 거래대금이 초기 스냅샷에서 정상 표시된다.
- [ ] 다른 페이지의 일반 조회가 불필요하게 제거되지 않았다.
- [ ] 오류 발생 시 한 페이지의 실패가 다른 페이지의 표시를 막지 않는다.

## 6. UI 확인 항목

사용자가 화면에서 확인할 항목:

- [ ] 업종 순위 화면을 새로 열었을 때 종목 목록이 표시된다.
- [ ] 매수 후보 화면을 열었을 때 후보 목록과 현재가가 표시된다.
- [ ] 보유 종목 화면을 열었을 때 종목명·현재가·손익이 표시된다.
- [ ] 수익 현황 화면을 열었을 때 보유 종목 기반 요약이 표시된다.
- [ ] 수익 상세 화면을 열었을 때 매수·매도 이력이 표시된다.
- [ ] 종목 분류 화면을 열었을 때 업종과 분류 대상이 표시된다.
- [ ] 종목 상세 화면을 열었을 때 5일 일봉 자료가 표시된다.
- [ ] 일반 설정 화면을 열었을 때 설정 자료가 표시된다.
- [ ] 설정에서 최소 거래대금을 바꾼 뒤 업종 순위 대상이 바뀐다.
- [ ] 페이지 이동 후 이전 화면의 종목이 남지 않는다.
- [ ] WebSocket 재연결 후 화면이 다시 채워진다.

## 7. 완료 기준

- [ ] 여덟 페이지 모두 페이지 이름만으로 초기 자료를 받는다.
- [ ] 종목 실시간 네 화면은 서버가 대상 코드를 정해 초기 스냅샷을 보낸다.
- [ ] 자료 중심 네 화면은 서버가 종목 구독 없이 해당 자료 스냅샷을 보낸다.
- [ ] 모든 지정 갱신 시점이 연결되어 있다.
- [ ] 중복 일반 조회와 프론트엔드 대상 목록 전달이 제거되었다.
- [ ] 단일 관리·이벤트 기반 갱신·단순성 원칙을 위반하지 않는다.
- [ ] 전체 기계적 검증이 통과한다.
- [ ] 독립 검토에서 회귀 위험이 없다고 확인된다.
- [ ] 사용자 화면 확인 항목을 완료 보고에 안내한다.
