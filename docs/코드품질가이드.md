# SectorFlow 코드 품질 가이드

> **상태**: 2026-08-06 작성. 기존 코드베이스 패턴 조사(6개 영역)를 기반으로 표준화.
> **목적**: AI 코딩 에이전트가 기존 코드의 일관된 패턴을 따라 고품질 코드를 작성하도록 안내.
> **관련 원칙**: P10(SSOT) · P22(데이터 정합성) · P23(일관성) · P24(단순성) · P25(격리된 실패)
> **작성 근거**: 백엔드 6개 영역(에러 처리·비동기·함수분리·네이밍·테스트·DB/설정/WS) + 프론트엔드 10개 항목 실제 코드 패턴 조사.
>
> **사용 방법**: 코드 작성 전 해당 영역 섹션을 확인. "표준 패턴"은 반드시 따르고, "금지"는 피할 것. 실제 예시는 코드베이스에서 직접 확인 가능.

---

## 0. 핵심 원칙 (모든 코드에 공통)

1. **기존 패턴 따르기** — 새 코드는 주변 코드의 패턴을 먼저 확인하고 일관되게 작성.
2. **단일 책임** — 한 함수/클래스/모듈은 하나의 명확한 작업만 수행.
3. **명시적 실패** — 빈값을 0/빈 문자열로 위장하지 말고 None/명시적 상태로 반환 (P20 폴백 금지).
4. **타입 힌트 필수** — 모든 함수 시그니처에 매개변수·반환 타입 명시.
5. **한글 docstring** — 함수·클래스·모듈에 한글 docstring 작성 (프로젝트가 한국어 기반).
6. **원칙 참조** — docstring에 해당 원칙 번호를 괄호로 명시 (예: `(P10 SSOT)`, `(P22 정합성)`).

## 1. 백엔드 에러 처리

### 표준 패턴

| 항목 | 표준 | 예시 위치 |
|---|---|---|
| 예외 로깅 | `logger.warning/error(..., exc_info=True)` — 스택 트레이스 포함 | `core/ls_connector.py:81` |
| 로그 레벨 구분 | `logger.error`=치명적(초기화·연결 실패), `logger.warning`=복구 가능(재시도·일시 실패) | `core/ls_connector.py:376,390` |
| CancelledError | 태스크 취소 시 `except asyncio.CancelledError: pass` (정상 종료) | `core/ls_connector.py:72-75` |
| 격리된 실패 | 기동 시 보조 작업 실패는 로그 후 계속 진행 (P25) | `web/app.py:61-64` |
| 폴백 금지 | 암호화·설정 로드 실패 시 평문 폴백 없이 명시적 상태 반환 (P20) | `core/encryption.py:140-145` |
| 재시도 | 지수 백오프 + 풀 지터 (`compute_backoff_delay`) | `core/auth_utils.py:40-55` |
| 실패 분류 | 일시 실패 vs 영구 실패 구분 (`classify_token_failure`) | `core/auth_utils.py:58-104` |
| HTTP 에러 | `HTTPException` + 구조화된 detail (`{"code", "message", "field"}`) | `web/routes/settings.py:86-89` |
| 결과 객체 | 예외 대신 상태·결과 객체 패턴 선호 (`EncryptResult`) | `core/encryption.py:126-145` |

### 금지

- **빈 `except: pass`** — CancelledError 제외, 예외를 삼키지 말 것.
- **`except Exception:` 남용** — 가능하면 구체적 예외 타입 지정 (`ValueError`, `ConnectionError` 등).
- **`exc_info=True` 누락** — 모든 예외 로깅에 스택 트레이스 포함.
- **HTTPException detail에 민감 정보** — 예외 메시지 원문 그대로 노출 금지.
- **폴백 기본값** — 실패 시 0/빈 문자열로 위장하지 말고 명시적 None/상태 반환.

### 실제 예시

```python
# 좋은 예: 로깅 + 재전파 (초기 연결 실패)
try:
    await self._socket.connect()
except Exception:
    logger.error("[연결] %s 초기 웹소켓 연결 실패 — 재연결 시작", _BROKER_DISPLAY, exc_info=True)
    asyncio.get_running_loop().create_task(self._on_socket_disconnect())
    raise

# 좋은 예: 결과 객체 패턴 (폴백 금지)
def encrypt_secret(plain: str) -> EncryptResult:
    if not plain or not plain.strip():
        return EncryptResult(state=SecretValueState.EMPTY)
    try:
        cipher = f.encrypt(plain.encode()).decode()
        return EncryptResult(state=SecretValueState.ENCRYPTED, ciphertext=cipher)
    except Exception:
        return EncryptResult(state=SecretValueState.DECRYPT_FAILED)  # 평문 폴백 없음

# 나쁜 예 (금지): 예외 삼키기
try:
    do_something()
except:
    pass  # 절대 금지
```

## 2. 백엔드 비동기 (async/await)

### 표준 패턴

| 항목 | 표준 | 예시 위치 |
|---|---|---|
| async 함수 | `async def` + 호출 시 `await` | `services/engine_loop.py:24` |
| 병렬 실행 | `asyncio.gather(*tasks, return_exceptions=True)` | `services/engine_loop.py:149-152` |
| 백그라운드 태스크 | `asyncio.create_task()` + 변수에 참조 유지 + `add_done_callback` | `web/app.py:72-73` |
| 타임아웃 | `asyncio.wait_for(coro, timeout=N.0)` — 명시적 초과 | `core/ls_connector.py:79` |
| 동시성 제어 | `asyncio.Lock`(재연결·매수), `Semaphore`(REST API), `Queue`(생산자-소비자) | `services/trading.py:254` |
| 취소 처리 | `task.cancel()` + `await task` + `CancelledError` 처리 | `services/engine_lifecycle.py:92-97` |
| 동기→비동기 | `asyncio.run`/`run_until_complete` 금지, `schedule_engine_task` 사용 | `services/engine_lifecycle.py:329-362` |
| 이벤트 루프 | 단일 루프(FastAPI 메인), `get_running_loop()`로 참조 | `web/app.py:2` |

### 금지

- **`asyncio.run` / `run_until_complete`** — 동기 함수에서 비동기 호출 시 사용 금지, `schedule_engine_task` 사용.
- **참조 유지 없는 `create_task`** — 태스크 변수에 저장하지 않으면 가비지 컬렉션됨.
- **`return_exceptions=True` 누락** — `gather`에서 예외 전파 방지 필수.
- **`await` 없이 코루틴 호출** — `schedule_engine_task`로 전달하는 경우는 예외이나 주석으로 의도 명시.

### 실제 예시

```python
# 좋은 예: 백그라운드 태스크 + 참조 유지 + 콜백
_gateway_task = asyncio.create_task(_gateway_loop())
_gateway_task.add_done_callback(
    lambda t: logger.warning("[게이트웨이] 루프 종료: %s", t.exception()) if t.exception() else None
)

# 좋은 예: 병렬 실행 + 예외 격리
results = await asyncio.gather(
    *[_fetch_one(bid) for bid in valid_broker_ids],
    return_exceptions=True,
)

# 좋은 예: 타임아웃 + 취소 처리
try:
    await asyncio.wait_for(self._ws.close(), timeout=5.0)
except Exception:
    logger.warning("[연결] %s 소켓 종료 실패", _BROKER_DISPLAY, exc_info=True)
```

| SQL | `?` 플레이스홀더 파라미터화 쿼리 (SQL 인젝션 방지) | `core/settings_file.py:293-297` |
| IN 절 | `placeholders = ",".join("?" * len(items))` 동적 생성 | `core/settings_file.py:295` |
| 트랜잭션 | `BEGIN TRANSACTION` → `commit`/`rollback` + 예외 시 `raise` 재전파 | `db/db_writer.py:96-119` |
| 스키마 생성 | `CREATE TABLE IF NOT EXISTS` (idempotent) | `db/stock_tables.py:10-18` |
| 컬럼 추가 | 존재 여부 체크 후 `ALTER TABLE` | `db/stock_tables.py:367-372` |
| 백업 | `.backup` 확장자만 정리 대상, 본체/`-shm`/`-wal` 절대 삭제 금지 | `db/database.py:60-130` |

### DB 금지

- **`*.db` 파일 직접 삭제·덮어쓰기** — 안전 규칙 1.
- **f-string으로 SQL 값 직접 삽입** — 반드시 `?` 플레이스홀더 사용.
- **`rollback` 없이 예외 처리** — 트랜잭션 실패 시 반드시 rollback + raise.
- **`raise` 누락** — P20 폴백 금지, 예외를 상위로 전파.
- **DB 스키마 변경 전 백업 없음** — `stocks.db`·`-shm`·`-wal` 백업 먼저 생성.

## 부록: 영역별 일관성 평가 요약

| 영역 | 일관성 | 주요 불일치 |
|---|---|---|
| 백엔드 에러 처리 | 양호 | `except Exception` 남용, `exc_info` 누락 ~20%, 커스텀 예외 계층 부재 |
| 백엔드 비동기 | 매우 양호 | 코루틴 전달 패턴 2건 (실제 누수 아님), `asyncio.timeout` 미사용 |
| 함수분리·네이밍 | 매우 양호 | 일부 함수 150줄 초과, 일부 타입 힌트 생략 |
| 프론트엔드 | 매우 양호 | `cssText`/`Object.assign` 혼용, 일부 파일 600줄 초과 |
| 테스트 | 매우 양호 | async fixture 금지 원칙 명시됨, monkeypatch 드물게 사용 |
| DB·설정·WS | 양호 | 구체적 예외 타입 부재, 스키마 버전 관리 부재, 캐시 무효화 불명확 |

> **참고**: 불일치 항목은 기존 코드의 소수 위치에서 발견되며, 대부분은 이미 일관된 패턴을 따르고 있음. 새 코드 작성 시 본 가이드의 표준 패턴을 따르고, 기존 불일치는 별도 리팩토링 시 정정.
