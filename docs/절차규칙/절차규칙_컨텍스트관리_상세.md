### 컨텍스트 관리 규칙

1. **작업량 기반 사전 분할**: 다단계 작업(신규 기능/구조 변경)의 작업량 분할은 섹션4 "다단계 작업 워크플로우" 2세션에서 수행. 단일 세션 내에서 작업량이 많은 경우 본 규칙 적용 — **분할 필수 기준: 수정 파일 3개 초과 또는 수정 라인 50줄 초과 시** (규칙 0-2-5 작업량 판단 기준과 동일). 각 단위는 독립적으로 완료·검증 가능한 크기로 설정. 분할 시 사용자에게 분할 계획을 보고 후 진행. 기준 미달이더라도 에이전트가 분할이 필요하다고 판단한 경우 분할 가능하되, 그 사유를 분할 계획 보고에 명시.
2. **단계 완료 시 컨텍스트 점검**: 각 작은 단계 완료 시 현재 컨텍스트 사용량을 점검. 사용량이 높아 다음 단계에서 오류 가능성이 있다고 판단되면, 다음 단계 진행 전 `HANDOVER.md`에 현재 진행 상태를 갱신하여 만일의 중단에 대비.
3. **사전 종료 권한**: 에이전트는 작업 중 컨텍스트 사용량이 많아져 오류 가능성이 있다고 판단되면, 현재 진행 상태를 `HANDOVER.md`에 기록하고 사용자에게 보고한 후 세션을 종료할 수 있음.
4. **HANDOVER.md 기록 의무 (인덱스 원칙)**: 세션 종료 전 반드시 다음을 기록. **HANDOVER는 인덱스 역할만 수행 — 상세 내용(사전조사/구현 계획/검증 상세)의 인라인 기록 금지** (규칙 8-2).
   - 완료된 작업 요약 — 수정 파일명 + 검증 결과 + **git 커밋 해시** (상세는 커밋 메시지에 기록, HANDOVER에 인라인 전개 금지)
   - 진행 중인 작업의 현재 단계 — 어디까지 했고, 어디서부터 이어하면 되는지 (docs/ 참조 경로 포함)
   - 다음 세션에서 수행해야 할 항목 — docs/ 참조 경로 또는 git 커밋 해시로 표기 (인라인 상세 금지)
5. **사용자 보고**: 세션 종료 시 사용자에게 진행 상태와 다음 단계를 명확히 전달.
6. **다음 세션 연속성**: 다음 세션 시작 시 "세션 시작 절차"의 HANDOVER.md 자동 확인(강제)에 따라 이어서 작업 진행.
7. **완료 작업 정리**: `HANDOVER.md`의 모든 섹션에서 완료된 항목은 즉시 정리. git history에 이미 기록되어 있으므로 중복 누적 방지.
   - **정리 시점 (2개)**:
     1. **작업 완료 시점 (즉시)**: 다단계 작업의 모든 단계 완료 시, "미해결 문제"·"다음 세션 진행 대기"에서 해당 항목 즉시 제거. 완료 후 다음 세션까지 잔존 금지.
     2. **새 세션 시작 시**: "직전 완료 작업"·"세션 개요"·"현재 상태"·"다음 단계" 섹션 최신 상태로 업데이트. **미집행 시 강제 압축** — 직전 완료 작업·세션 개요가 1건 초과 누적 시, 새 세션 시작 절차에서 최근 1건만 남기고 나머지 제거 (git history 참조).
   - **섹션별 유지 건수 + 줄수 상한**:
     - `직전 완료 작업` — 최근 1건, **항목당 3줄 이하** (수정 파일 + 검증 결과 + 커밋 해시만, 상세는 git history 참조)
     - `세션 개요` — 최근 1건
     - `미해결 문제` — 완료된 항목 즉시 제거 (해결 완료 보관용 섹션 생성 금지 — 규칙 8-1)
     - `다음 세션 진행 대기` — 완료된 항목 즉시 제거, **항목당 3줄 이하** (작업명 + 현재 단계 + docs/ 참조 경로)
   - **사각지대 방지**: "미해결 문제"에 등록된 항목이 완료된 경우, 완료 보고와 함께 해당 항목을 섹션에서 제거. "완료된 항목을 별도 보관 섹션으로 이관" 금지 (git history가 단일 진실 소스).
8. **HANDOVER.md 수정 원칙 (read-before-write)**: `HANDOVER.md` 수정 시 반드시 read 먼저 수행. 기존 내용을 보존한 후 병합. write 도구로 덮어쓰기 금지 — 기존 섹션 내용을 읽어 확인한 후에만 수정/추가. 실수로 기존 내용을 삭제하는 사고 방지.
8-1. **HANDOVER.md 표준 섹션 구조 (P23 일관성)**: `HANDOVER.md`는 **다음 세션 인계 + 인덱스 역할**만 수행 (0절 역할 표 · 규칙 8-2). **git 추적 대상 아님** — 작업 디렉터리 파일로만 유지되며 커밋에 포함하지 않음 (규칙 0-6-2). 다음 표준 섹션 구조 유지. **표준 섹션 외 임의 섹션 생성 금지** (예: "해결 완료 문제 (참고용)" 같은 보관용 섹션 생성 금지 — 완료된 항목은 git history가 단일 진실 소스이므로 HANDOVER에서 제거만 수행).
    - `세션 개요` — **메타만 담당** (중복 회피 — 본문은 `직전 완료 작업`이 담당): 날짜, 작업 한글명, 전체 상태(진행 중/완료/승인 대기), 참조 문서(계획서 경로). 최근 1건 유지 (규칙 7).
    - `직전 완료 작업` — **본문만 담당**: 최근 1건, **항목당 3~5줄** (수정 파일 + 검증 결과 + 커밋 해시 + 완료된 작업 1줄 요약). 상세 구현 내역은 git history 참조 (규칙 7, 8-2). `세션 개요`와 동일 세션을 다루되 담당 정보가 겹치지 않도록 역할 분리.
    - `다음 세션 진행 대기` — 진행 중 작업의 단계 진행 상황 + **승인 상태**(승인 완료/승인 대기 — 필수기재 항목 2 참조) + 참조 문서(계획서 경로) + **이번 세션 검증 누락**(필수기재 항목 4) + **이번 세션 가정·위험**(필수기재 항목 5). **항목당 3줄 이하** (검증 누락·가정·위험은 각각 1줄 이하, 해당 없음 시 "없음" 명시). 완료 항목 즉시 제거 (규칙 7).
    - `미해결 문제` — 규칙 9 기록 대상. 완료 항목 즉시 제거 (규칙 7).
    - 다단계 작업 진행 중인 경우 `다음 세션 진행 대기` 섹션에 단계 진행 상황 + 참조 문서(디자인/태스크 파일 경로) 명시
    - 계획서 파일 삭제(규칙 10) 시 `세션 개요`·`다음 세션 진행 대기`의 참조 문서에서 해당 경로 제거 (P10 SSOT — 잔존 참조 방지)
    - **필수 기재 항목 (강제 — 규칙 0-6-2 자동 갱신 시 빠짐없이 기재)**: 코드 수정 작업 완료 시 `HANDOVER.md` 갱신 시 아래 5항목을 **빠짐없이** 기재. 해당 없음 시에도 "없음"/"해당 없음"으로 명시적 표기 (생략 금지 — P21 사용자 투명성). **코드 수정 없는 작업은 갱신 의무 예외 (규칙 0-6-2) — 본 항목 적용 안 함.** 항목 4·5는 외부 검증 자료(AI 에이전트 세션 인계 모범 사례)에서 "가장 많이 빠뜨리는 항목"으로 꼽힌 것을 반영 — 검증 문화("완료 판정은 기계적 검증 결과로만")와 일관되게 다음 세션에 미검증 상태가 묵히 넘어가는 모순 방지.
      1. **완료된 작업 요약** — 이번 세션에서 완료된 작업 내용 3~5줄. `직전 완료 작업` 섹션에 기재. 일반 사용자 용어 우선(규칙 0-8 1항), 수정 파일 + 검증 결과 + 커밋 해시 포함.
      2. **다음 안전 동작 + 진행률 + 승인 상태** — 다음 세션에서 이어서 해야 할 작업, 현재 진행률, 승인 상태. `다음 세션 진행 대기` 섹션에 기재. 진행률은 "단계 N/M" 형태 명시(예: "단계 3/8 완료, 다음 단계 4/8 예정"). **승인 상태 필수** — "승인 완료—진행 가능" / "승인 대기—코드 수정 금지" 중 하나 명시 (규칙 0 준수 — 다음 세션 AI가 핸드오버만 보고 승인 여부 판단 가능해야 함). **이어할 곳 포인터** — 다단계 작업 시 설계/태스크 파일 경로 + 이어할 섹션명 명시 (예: "docs/태스크/xxx.md '작업 순서' 4단계부터"). **다음 안전 동작** — "재검증 없이 안전하게 할 수 있는 가장 구체적인 한 동작"을 명시 (예: "실패한 테스트 파일만 먼저 실행해 원인 확인"). 모호한 "여기서 이어" 금지 — 다음 세션이 헤매지 않도록 구체적 동작 한 줄. 단일 세션 완료 작업은 "없음(전체 완료)".
      3. **참고 문서 경로** — 관련 설계 파일(`docs/설계서/*.md`)·태스크 파일(`docs/태스크/*.md`)·조사 파일(`docs/조사보고서/*.md`)·테스트 파일 경로. `직전 완료 작업` 또는 `다음 세션 진행 대기` 섹션의 참조 문서 란에 기재. 해당 문서 없으면 "참고 문서: 없음" 명시.
      4. **이번 세션 검증 누락 (강제 — P21 투명성)** — 이번 세션에서 **아직 검증하지 않은 것**을 명시. `다음 세션 진행 대기` 섹션에 1줄로 기재. 예: "화면 스크롤은 확인, 모바일 화면 표시 미확인", "런타임 기동만 확인, 전체 테스트 미실행". 해당 없음 시 "검증 누락: 없음" 명시. **목적**: "완료 판정은 기계적 검증 결과로만" 원칙과 일관되게, 다음 세션이 미검증 상태를 묵히 물려받는 모순 방지. "미해결 문제"(이미 발견된 문제)와 구분 — 본 항목은 "아직 확인 안 한 것"용.
      5. **이번 세션 가정·위험 (강제 — P21 투명성)** — 이번 세션에서 세운 가정 중 틀릴 수 있는 것 + 위험을 1줄로 명시. `다음 세션 진행 대기` 섹션에 기재. 예: "가정: 설정 캐시가 갱신된 것으로 전제", "위험: 화면 확인 없이 빌드만 통과". 해당 없음 시 "가정·위험: 없음" 명시. **목적**: 다음 세션이 틀린 가정을 그대로 물려받아 잘못된 방향으로 진행하는 것 방지. 위험도가 높아 본격 추적이 필요한 것은 "미해결 문제"로 승격 — 본 항목은 가벼운 가정·위험용.
8-2. **HANDOVER 인덱스 원칙 (강제 — P10 SSOT / P24 단순성)**: `HANDOVER.md`에 상세 내용을 인라인으로 기록하는 것을 금지. HANDOVER는 다음 세션 인계 + 인덱스 역할만 수행 (0절 역할 표 · 규칙 8-1). **git 추적 대상 아님** — 작업 디렉터리 파일로만 유지 (규칙 0-6-2). 상세 구현 내역의 단일 진실 소스는 git 커밋 메시지 + docs/ 파일.
    - **인라인 기록 금지 대상**: 사전조사 결과, 구현 계획, 수정 상세 내역(줄 단위 변경), 검증 상세(테스트 개수/로그), 아키텍처 원칙 부합 분석, 영향 범위 분석, UI 기준 화면 변화 설명.
    - **상세 보관 위치**:
      - 다단계 작업 (설계/태스크/조사보고서): `docs/설계서/*.md`, `docs/태스크/*.md`, `docs/조사보고서/*.md` (완료 시 규칙 10에 따라 삭제 → git history만 잔존)
      - 완료된 작업 구현 상세: **git 커밋 메시지** (단일 진실 소스 — 규칙 7 "git history가 단일 진실 소스" 부합)
    - **HANDOVER에 허용되는 내용**: 작업 식별자(세션 ID), 1줄 요약, 수정 파일 목록, 검증 결과(합격/불합격 + 커밋 해시), docs/ 참조 경로, 미해결 문제(규칙 9 형식 준수), **승인 상태**(승인 완료/승인 대기 — 0절 역할 표 "다음 세션이 어떤 승인 상태로 이어지는가" 충족), **다음 안전 동작**(필수기재 항목 2), **이번 세션 검증 누락**(필수기재 항목 4), **이번 세션 가정·위험**(필수기재 항목 5) — 모두 1줄 이하로 인덱스 수준에서 기재, 상세 전개 금지.
    - **커밋 메시지 의무**: 구현 상세(수정 사유, 변경 내역, 검증 상세)는 코드 커밋 메시지에 기록. HANDOVER에 기재한 커밋 해시를 통해 코드 커밋을 조회. 커밋 메시지에 "왜(why)" 중심 간결 기록 (Git 규칙 준수).
    - **적용 예시 (직전 완료 작업 항목)**:
      ```
      ### T3-S32 체결강도 매수차단 제거 문서 정리 — 완료 (2026-07-23)
      - 수정: ARCHITECTURE.md + p25 문서 + HANDOVER.md (3파일), 삭제: 설계/태스크 파일 (2파일)
      - 검증: 잔존 참조 0건 / 커밋 3433391
      ```
9. **작업 중 발견 문제 기록 의무 (강제)**: 메인 작업 도중 우연히 발견한 아키텍처 위반(P원칙), 오류, 잠재적 버그, dead code, 폴백 패턴, 아키텍처 원칙에 부합하는 더 나은 구조(개선점) 등은 현재 세션에서 즉시 해결하지 못하더라도 **반드시** `HANDOVER.md`의 "미해결 문제" 섹션에 기록. 사용자가 직접 해결할 수 없으므로, 에이전트가 발견 즉시 기록하지 않으면 영영 누락됨.
   - **기록 형식**: 파일명:줄번호, 위반 원칙 번호(P10/P16/P20 등) 또는 부합 원칙 번호(개선점의 경우), 증상/개선내용 1문장, (가능시) 수정 방향.
   - **개선점 인정 기준 (P24 준수)**: 주관적 취향이 아닌 **객관적 근거**가 있는 것만 — (a) 특정 P원칙에 부합하여 현재 구조보다 정량적으로 더 단순/일관/정합 (b) 기존 공통 자산 재사용으로 중복 제거 (c) 명확한 중복·dead code·폴백 회피 가능. 근거 없는 "이렇게 하면 더 좋을 것 같음"은 기록 대상 아님.
   - **중복 회피**: 이미 "미해결 문제"에 등록된 항목은 중복 기록하지 않고, 새 정보가 있으면 기존 항목에 갱신.
   - **세션 종료 보고**: 세션 종료 시 "미해결 문제"에 신규 추가된 항목이 있으면 사용자에게 명시적으로 보고 ("이번 세션에서 N건의 신규 문제/개선점을 발견하여 미해결 문제에 등록했습니다").
   - **다음 세션 우선순위**: 다음 세션 시작 시 `HANDOVER.md`의 "미해결 문제" 섹션을 확인하고, 사용자와 함께 해결 우선순위를 정함.
10. **작업 산출물 정리 (강제 — 작업 완료 시).** 작업 완료 후 최종 커밋 시, 아래 3항목의 임시 산출물을 정리. git history에 영구 기록되므로 작업 디렉터리에 보관 불필요 — 루트 폴더 및 작업 디렉터리에 불필요 파일 누적 방지 (P24 단순성 · P10 SSOT).
    - **(1) 계획서 파일 삭제 (다단계 작업 완료 시)**: 다단계 작업 워크플로우(섹션4 "다단계 작업 워크플로우")의 모든 단계 완료 후 최종 커밋 시, 해당 작업의 계획서 파일을 함께 삭제.
      - **삭제 대상**: `docs/태스크/*.md` (태스크 파일), `docs/설계서/*.md` (디자인 파일), `docs/*-design*.md`·`docs/*-tasks.md` (설계·태스크 파일 — 파일명 접두사 무관, 다단계 작업 완료 산출물 전체 포함), `docs/coupling-*-matrix.md`·`docs/coupling-*-index.md`·`docs/coupling-*-backref.md`·`docs/coupling-*-callgraph.md`·`docs/coupling-*-boundary.md`·`docs/coupling-*-direct.md`·`docs/coupling-*-normalization.md` (감사 산출 매트릭스 문서), `docs/*_audit_*.md`·`docs/*-audit-*.md` (감사 계획·태스크 문서 — architecture_audit_*, dead-code-audit_*, duplication-audit_*, coupling-audit-* 전부 포함), `docs/조사보고서/*.md` (조사 보고서). 모든 완료된 작업의 계획/태스크/감사/조사 문서는 삭제 대상 — git 히스토리가 단일 진실 소스(SSOT)이므로 작업 디렉터리에 별도 보존 불필요.
      - **삭제 시점**: 모든 단계 완료 후 최종 커밋에 삭제 포함 (동일 커밋)
      - **삭제 제외 (혼동 주의)**:
        - `docs/참고_*.md`·`docs/reference_*.md` 등 참고자료 (외부 자료 정리 — 유지)
        - `docs/api_specs/` 등 API 스펙 (사용 중인 외부 API 문서 — 유지)
        - 진행 중인 작업의 계획서·감사·조사 문서 (일부 단계만 완료 시 유지)
      - **삭제 전 확인**: `HANDOVER.md` "참조 문서" 섹션에서 해당 계획서 경로도 함께 정리 (P10 SSOT — 잔존 참조 방지)
      - **커밋 메시지**: 삭제된 계획서 파일명 명시
      - **승인**: 삭제 전 사용자 승인 필수 (규칙 0 — 파일 삭제는 코드 제거와 동일 취급, 규칙 0-3 롤백 규칙 연계)
    - **(2) DB 백업 파일 삭제 (마이그레이션 검증 완료 시)**: DB 스키마 변경/마이그레이션 작업 완료 후 런타임 검증(0-1-2 표준 검증 절차) 이상 없으면, db-backup 스킬이 생성한 타임스탬프 백업 파일(`*.db.*.backup`, `*.db-shm.*.backup`, `*.db-wal.*.backup`)을 삭제.
      - **삭제 조건**: 마이그레이션 후 런타임 기동 정상 + 핵심 데이터 조회 이상 없음 확인 후
      - **삭제 시점**: 검증 완료 후 다음 커밋에 포함 (또는 검증 완료 보고 시 사용자 승인 후 별도 삭제)
      - **승인**: 삭제 전 사용자 승인 필수 (안전 규칙 1 연계 — `.db` 원본 파일이 아닌 백업 파일만 대상)
    - **(3) 임시 산출물 정리 (작업 완료 시)**: 작업 과정에서 생성한 임시 파일(테스트용 스크립트, 디버그 로그, 임시 출력물 등)을 완료 시 삭제. 루트 폴더 및 작업 디렉터리에 불필요 파일 잔존 금지.

    - **(4) 작업 상태 SSOT 정리 (코드 변경 없는 문서 상태 갱신 시)**: 코드 변경 없이 문서 상태만 갱신하는 작업 완료 시, `HANDOVER.md`의 상태 표기가 코드 실제 상태와 일치하는지 확인·갱신. 위반 항목 해결 완료 시 진행률 카운트·잔여 세션 수를 실제와 일치화. 감사 문서는 완료 시 규칙 10-(1)에 따라 삭제되므로, 감사 진행 중에는 해당 감사 문서의 상태 표(☐/◐/☑)도 실제와 일치시키되 완료 시 삭제. P10(SSOT — 코드-문서 불일치 차단) · P23(일관성 — 상태 표기 일관).
