## 0. 보고 형식 통일 원칙 (강제 — 모든 보고에 적용)

> **목적**: 사용자가 코딩 지식 없이도 한눈에 파악할 수 있도록, 보고는 표 형태를 우선한다. 본 형식은 `규칙 0-8`과 `세션 보고 포맷`(섹션4)의 구일 표준(P10 SSOT)이다. 각 `SKILL.md`는 본 형식을 참조하고, 스킬별 추가 항목은 기존 표의 새 행(row)으로만 추가한다(임의 표 생성 금지). 보고는 추가 결정이 필요한 경우에만 승인 요청 역할을 한다. 작업 완료 보고는 종료 알림이다.

### 0.1 표 형식 강제 (세션 종료 계열 보고)

세션 종료 계열 보고(완료·단계 완료·중단·보류)는 반드시 표 형식으로만 작성. 이모지 요약 형식은 "1줄 질답·진행 중 간단 알림"에만 허용되며 완료 보고에는 사용 불가.

표 형식 강제 이유 3가지:
1. **항목 누락 기계적 방지** — 표 칸이 비어 있으면 한눈에 보여 누락 즉시 발견.
2. **한눈 상태 파악** — 사용자가 코딩 지식 없이도 표만 보고 전체 상태 파악 가능.
3. **봉인 규칙 명확 종결** — 세션 종료 체크리스트 표의 마지막 행(사용자 결정)으로 보고가 명확히 종결되어 완료 후 추가 질문·제안이 붙을 수 없음.

### 0.2 표 구조 통일 규칙 (강제 — 5항목)

| 항목 | 내용 |
|---|---|
| 표 구조 | 모든 표는 2칸 구조(`항목 \| 내용`)만 사용. 3칸 이상 표 금지. |
| 항목당 1행 | 한 항목이 한 행을 차지. 여러 항목을 한 행에 몰아넣지 않음. |
| 이전/이후 비교 | 같은 행의 내용 칸에서 "전: <이전> / 후: <이후>" 형식으로 표현. |
| 표 구성 고정 | 세션 유형별 표 세트 고정(아래 0.4). 생략 불가. 해당 없으면 "해당 없음" 행으로 명시. |
| 표 순서 고정 | 아래 7개 표를 번호 순서대로 배치. 순서 변경 금지. |

### 0.3 보조 도구 추가 표 금지 (강제)

| 항목 | 내용 |
|---|---|
| 임의 표 생성 | 보조 도구(SKILL.md)가 임의로 새 표를 추가하는 것 금지. |
| 추가 항목 | 기존 표의 새 행으로만 추가. 행 제목은 "도구명: 항목명" 형식. |
| 구조 준수 | 추가 행도 2칸 구조(`항목 \| 내용`) 준수. |

### 0.4 세션 유형별 고정 표 세트

| 항목 | 내용 |
|---|---|
| 코드 수정 완료 세션 | 포함 표: 1·2·3·4·5·6(다단계 시)·7. 전체 표. 표 6은 다단계 작업 시만, 단발 작업은 "해당 없음" 1행 |
| 조사/의견 제시 세션 | 포함 표: 1(변경 전만)·4·7. 표 1은 '문제/필요성'·'근본 원인' 행만 채우고 나머지 "조사 중" |
| 1줄 질답·진행 중 간단 알림 | 표 형식 생략, 이모지 요약 또는 간결 텍스트 허용. 세션 종료 계열 보고가 아닌 경우만 해당 |

> **생략 금지 (강제)**: 세션 종료 계열 보고에서 해당 없는 표/행은 생략하지 않고 "해당 없음"으로 명시. 단, 표 6은 단발 작업 시 표 전체를 "해당 없음" 1행으로 대체 가능. 표 7(세션 종료 체크리스트)은 절대 생략 불가.

### 0.5 7개 표 (기본 메뉴 — 고정 순서)

1. 변경 내용 표 · 2. 아키텍처 원칙 판별 표 · 3. 검증 결과 표 · 4. 최종 판별 표 · 5. 커밋 및 핸드오버 표 · 6. 설계 완료 기준 충족 표(다단계 작업 시) · 7. 세션 종료 체크리스트(필수).

### 0.6 표 작성 공통 원칙

`ARCHITECTURE.md` 부록 B 표준 용어 사전 준수 — "업종" not "섹터", "종목" not "주식", "매수 후보" not "바이 리스트", "보유 종목" not "홀딩/포지션", "매수" not "Buy/구매", "매도" not "Sell/판매".

### 0.7 다단계 작업 단계 표시 (강제 — 태스크 파일 있는 작업)

태스크 파일(`docs/태스크/*.md`)이 있는 다단계 작업의 보고 제목은 `전체 N단계 중 N단계 시작` / `전체 N단계 중 N단계 완료` 형식으로 작성. N(전체 단계 수)과 N(현재 단계)은 태스크 파일 기준. 단계가 추가·병합·삭제되면 **태스크 파일을 먼저 갱신**한 뒤 보고에 반영 — 태스크 파일과 보고의 단계 수가 항상 일치해야 함(P10 SSOT · P23 일관성). **단, 마지막 단계(전체 완료) 시에는 태스크 파일 갱신 생략** — 갱신 직후 삭제되므로 무의미 (P24 단순성). 보고 제목의 단계 수는 기존 태스크 파일 기준 그대로 작성. 태스크 파일 없는 단발 작업·조사 세션은 기존 형식(세션 한글명만) 유지.

### 0.8 이모지-표 관계 (중복 금지 — 규칙 0-8 3항 + 표 형식 강제)

세션 종료 계열 보고(완료·단계 완료·중단·보류)는 반드시 표 형식만 사용 — 이모지 요약 줄 사용 금지. 이모지 요약 줄은 "1줄 질답·진행 중 간단 알림"에만 허용. 표를 쓸 때 각 이모지가 담당하는 항목:
- `💡 변경내용` → **변경 내용 표**
- `✅ 원칙` → **아키텍처 원칙 판별 표**
- `⚠️ 경고` → **최종 판별 표**의 '경고/특이사항' 행
- `📦 커밋` / `🚀 푸시` / `📝 HANDOVER` → **커밋 및 핸드오버 표**
- `검증 결과 표`는 `✅ 원칙` 표 다음 또는 별도로 배치(P21 사용자 투명성 강화).

### 표 7. 세션 종료 체크리스트 (필수 — 생략 불가)

> **보고서 마지막에 반드시 배치** — 작업 결과와 종료 상태를 사용자가 알 수 있게 하는 표. `작업 완료`와 `단계 완료·대기`에서는 승인 요청 없이 마무리하고, `중단·보류`에서만 재개에 필요한 결정을 적는다. 규칙 0-7(커밋/푸시/HANDOVER 독립 줄 명시)은 본 체크리스트 표의 행으로 충족 — 세션 종료 계열 보고는 표 형식 강제이므로 이모지 독립 줄은 1줄 질답·진행 중 간단 알림에만 적용.
>
> **핸드오버 갱신·커밋 누락 금지 (강제)**: "Git 커밋" 행과 "HANDOVER 갱신" 행은 세션 종료 계열 보고에서 **절대 생략 불가**. 코드 변경이 없으면 "불필요(변경 없음)"/"갱신 없음(코드 수정 없음)"으로 명시하되, 행 자체를 빼거나 누락하는 것은 금지. 사용자가 보고만 보고도 커밋·핸드오버 상태를 반드시 확인할 수 있어야 함(규칙 0-7 강화).

| 항목 | 내용 |
|---|---|
| 검증 | <✅ 통과 / ❌ 실패(사유) — 기계적 + 의미적(작업 완료 체크리스트 1단계)> |
| Git 커밋 | <완료(사용자용 요약)/불필요(변경 없음) — 상세 식별자는 내부 인계 문서에만 기록> |
| HANDOVER 갱신 | <완료/보류(사유)/갱신 없음(코드 수정 없음 — 규칙 0-6-2 예외)> |
| Push | <안 함(기본)/승인 시 수행(사용자 명시 요청 시만)> |
| 현재 상태 | <작업 완료/단계 완료·대기/중단·보류> |
| 사용자 결정 | <작업 완료·단계 완료: `없음(작업 종료)` / 중단·보류: 재개에 필요한 결정 또는 없음> |
| 사용자 확인 필요 | <해당 없음 또는 사용자가 직접 확인할 사항 — UI 조작 기준> |

> **작성 요령**:
> - "검증"은 기계적(typecheck/test/build/pytest/RuntimeWarning) + 의미적(태스크 완료·원칙 부합·설계 준수·부작용) 통과 여부. 실패 시 세션 종료 절차 2단계에서 중단되므로 본 체크리스트 단계에 도달 불가 — 실패 행은 사실상 "추가 수정 필요" 상태와 함께 표시.
> - "Git 커밋"/"HANDOVER 갱신"은 규칙 0-6-2 자동 수행 결과를 그대로 표시 — 사용자가 지시하지 않아도 AI가 수행한 결과.
> - "현재 상태"는 3가지 중 택1 — 작업 완료, 단계 완료·대기, 중단·보류.
> - "사용자 결정"은 작업 완료·단계 완료에서는 반드시 `없음(작업 종료)`으로 표시. 중단·보류에서만 재개에 필요한 결정이 있을 때 그 내용을 적는다.
> - 완료 보고 뒤에는 다음 단계 진행 여부를 묻지 않는다. 다음 단계와 승인 상태는 `HANDOVER.md`에만 기록.
> - "사용자 확인 필요"는 UI 조작으로 안내(사용자 의사소통 규칙 1). 터미널/콘솔 확인 요청 금지. 해당 사항 없으면 "해당 없음" 명시(행 생략 금지).
> - **표 5와의 중복 회피 (P24)**: 표 5가 커밋/푸시/HANDOVER/설계·태스크 문서 갱신/미해결/다음 세션을 담당하므로, 표 7은 종료 체크리스트 관점(검증·현재 상태·사용자 결정·사용자 확인)에 집중하되 커밋·HANDOVER 행은 중복 표시(사용자가 표 7만 봐도 종료 상태 파악 가능하도록).

> **이모지 줄 사용 조건 (규칙 0-8 3항 + 표 형식 강제)**: 세션 종료 계열 보고(완료·단계 완료·중단·보류)는 표 형식만 사용하므로 이모지 요약 줄 사용 금지. 이모지 요약 줄은 "1줄 질답·진행 중 간단 알림"에만 독립된 줄로 출력.

## 2. 이모지 요약 형식 (1줄 질답·진행 중 간단 알림 전용 — 세션 종료 계열 보고 사용 금지)

> **사용 제한 (강제)**: 본 이모지 요약 형식은 "1줄 질답·진행 중 간단 알림"에만 사용. 세션 종료 계열 보고(완료·단계 완료·중단·보류)는 반드시 위 7개 표 형식으로만 작성 — 본 이모지 형식 사용 시 규칙 위반.

```
## 세션 완료 보고: <세션 한글명>

한 줄 요약: <이번 작업으로 무엇이 달라졌는가 — 사용자 관점 1문장>

💡 변경내용: <사용자가 확인할 수 있는 변화를 일반 사용자 용어로. 없으면 "화면 변화 없음(내부 개선)">

✅ 원칙: <P1~P25 전체 판정 결과와 근거. 예: "P1 ✅ — W1 단일 흐름 유지". 하나라도 ❌/보류이면 완료 보고가 아니라 중단·보류 보고>

⚠️ 경고: <작업 중 발견한 오류·위험·잠재 버그. 없으면 "없음". 규칙 0-9 · 규칙 9 — 발견 시 HANDOVER "미해결 문제"에도 기록>

📦 커밋: <완료 여부·사용자용 요약> (변경 커밋 시) / 없음(변경 없음)
🚀 푸시: 안 함(기본) / 완료(사용자가 명시 요청 시)
📝 HANDOVER: 완료(<내용 요약 1줄>) / 보류(<사유>) / 갱신 없음(코드 수정 없음)
(위 3항목은 반드시 각각 독립된 줄로 표시. "커밋에 포함"·"커밋과 함께" 등 통합·간접 표현 금지 — 규칙 0-7)

상태: <작업 완료 / 단계 완료·대기 / 중단·보류>
사용자 결정: <작업 완료·단계 완료 시 "없음(작업 종료)" / 중단·보류 시 재개에 필요한 결정>
사용자 확인: <항목 또는 없음>
```

> `작업 완료` 또는 `단계 완료·대기`인 경우 위 내용이 마지막이다. 다음 단계 질문·승인 요청·추가 작업 권유를 붙이지 않는다.

> **표를 쓰는 정식 보고에서는 세션 종료 체크리스트(표 7)가 이 역할을 담당 — 이모지 🔔 줄과 중복 기재 금지.**

## 3. 선택 항목 및 금지

**선택 항목** (해당 시만):
- `롤백 사유` — 사용자 승인으로 롤백한 경우 사유 요약. 최종 판별 표의 '경고/특이사항' 행에 추가(규칙 0-3).

**금지**: 기술 참조(파일 경로/줄번호/함수명) 노출(규칙 0-8 1항) · 터미널 명령어 안내 · API 직접 호출 안내(규칙 0-8 1항) · `작업 완료` 또는 `단계 완료·대기` 보고 뒤에 다음 단계 제안·질문·승인 요청·추가 작업 권유를 붙이는 행위.

**작성 완료 후 액션**: 검증 완료 → (변경 있으면 커밋) → HANDOVER.md 갱신 → 종료 상태에 맞는 완료 또는 중단·보류 보고(채팅 출력 — 세션 종료 체크리스트 포함). 푸시는 사용자가 명시적으로 요청한 경우에만 별도로 진행(Git 규칙 "DO NOT push unless explicitly asked").
