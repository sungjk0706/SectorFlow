# 완료 보고 템플릿 (복사해서 채우기만 하면 됨)

> **역할**: 이 파일은 완료 보고를 작성할 때 빈 칸을 채우기만 하면 되는 단일 템플릿입니다. 보고 형식 기준은 `절차규칙_보고_상세.md`(단일 진실 소스)에 정의되어 있으며, 본 파일은 그 기준을 복사용 양식으로 옮겨놓은 것입니다. 본 파일과 기준 규정이 다를 경우 기준 규정이 우선합니다.
>
> **표 형식 강제 (세션 종료 계열 보고)**: 완료 보고·단계 완료 보고·중단·보류 보고는 반드시 아래 표 형식으로만 작성. 이모지 요약 형식은 "1줄 질답·진행 중 간단 알림"에만 허용되며 세션 종료 계열 보고에는 사용 금지. 표 형식 강제 이유 3가지:
> 1. **항목 누락 기계적 방지** — 표 칸이 비어 있으면 한눈에 보여 누락 즉시 발견.
> 2. **한눈 상태 파악** — 사용자가 코딩 지식 없이도 표만 보고 전체 상태 파악 가능.
> 3. **봉인 규칙 명확 종결** — 세션 종료 체크리스트 표의 마지막 행(사용자 결정)으로 보고가 명확히 종결되어 완료 후 추가 질문·제안이 붙을 수 없음.
>
> **표 구조 통일 규칙 (강제 — 5항목)**:
> 1. 모든 표는 2칸 구조(`항목 | 내용`)만 사용. 3칸 이상 표 금지.
> 2. 항목당 1행 — 한 항목이 한 행을 차지. 여러 항목을 한 행에 몰아넣지 않음.
> 3. 이전/이후 비교는 같은 행의 내용 칸에서 "전: <이전> / 후: <이후>" 형식으로 표현.
> 4. 표 구성 고정 — 세션 유형별 표 세트 고정(아래). 생략 불가. 해당 없으면 "해당 없음" 행으로 명시.
> 5. 표 순서 고정 — 아래 7개 표를 번호 순서대로 배치. 순서 변경 금지.
>
> **세션 유형별 고정 표 세트**:
> - 코드 수정 완료 세션: 표 1·2·3·4·5·6(다단계 시)·7. 표 6은 다단계 작업 시만, 단발 작업은 "해당 없음" 1행.
> - 조사/의견 제시 세션: 표 1(변경 전만 — '문제/필요성'·'근본 원인' 행만 채우고 나머지 "조사 중")·4·7.
> - 1줄 질답·진행 중 간단 알림: 표 형식 생략, 이모지 요약 또는 간결 텍스트 허용(세션 종료 계열 보고가 아닌 경우만).
>
> **사용법**: 작업 완료 후 "종료 실행 순서"(검증 통과 → 저장 → 인계 갱신 → 보고)를 모두 수행한 뒤, 아래 템플릿을 복사하여 빈 칸을 채우고 채팅에 출력합니다. 일반 사용자 용어로 작성하며, 기술 식별자(파일 경로·저장 해시·함수명 등)는 사용자 응답에 노출하지 않습니다.
>
> **봉인 주의**: 완료 보고 뒤에 다음 단계 제안·질문·승인 요청을 붙이지 않습니다. 단, 종료 체크리스트(아래 7번)는 보고의 필수 부분이므로 생략하지 않습니다 — 봉인은 체크리스트 이후의 추가 내용만 금지합니다.

## 세션 완료 보고: <세션 한글명>

> **다단계 작업 시 제목 형식 (강제)**: 태스크 파일이 있는 다단계 작업은 제목을 `전체 N단계 중 N단계 완료: <세션 한글명>` 형식으로 작성. N(전체)·N(현재)은 태스크 파일 기준. 단계 변경 시 태스크 파일 먼저 갱신 후 보고에 반영. **단, 마지막 단계(전체 완료) 시에는 태스크 파일 갱신 생략** — 갱신 직후 삭제되므로 무의미. 보고 제목의 단계 수는 기존 태스크 파일 기준 그대로 작성. 태스크 파일 없는 단발 작업은 위 제목 형식 그대로 사용.

### 3. 검증 결과 표

| 항목 | 내용 |
|---|---|
| 정적 검증 | <통과/실패(사유)/해당 없음> |
| 빌드 | <통과/실패(사유)/해당 없음> |
| 테스트 | <통과(수치, 예: pytest 2806 passed)/실패(사유)/해당 없음> |

### 5. 커밋 및 핸드오버 표

> "Git 커밋" 행과 "HANDOVER 갱신" 행은 절대 생략 불가. 코드 변경이 없으면 "불필요(변경 없음)"/"갱신 없음(코드 수정 없음)"으로 명시. 표 7이 종료 체크리스트 관점(검증·현재 상태·사용자 결정·사용자 확인)을 담당하므로, 본 표는 커밋·인계·문서 갱신·미해결·다음 세션 예정을 담당.

| 항목 | 내용 |
|---|---|
| Git 커밋 | <완료(사용자용 요약)/불필요(변경 없음)> |
| Git 푸시 | <안 함(기본)/완료(사용자 명시 요청 시만)> |
| HANDOVER 갱신 | <완료/보류(사유)/갱신 없음(코드 수정 없음)> |
| 설계 문서 갱신 | <해당 없음/완료 — 다단계 설계 단계에서만 해당> |
| 태스크 문서 갱신 | <해당 없음/완료 — 다단계 태스크 단계에서만 해당> |
| 미해결 항목 | <없음/목록> |
| 다음 세션 예정 | <없음/요약 — 다단계 작업 시 다음 단계 + 진행률> |

### 6. 설계 완료 기준 충족 표 (다단계 작업 시만)

> 단일 세션 작업·조사 세션은 아래 1행으로 대체(표 전체 생략 불가).

### 7. 세션 종료 체크리스트 (필수 — 생략 불가)

| 항목 | 내용 |
|---|---|
| 검증 | <✅ 통과 / ❌ 실패(사유) — 기계적 + 의미적> |

| 사용자 확인 필요 | <해당 없음 또는 사용자가 직접 확인할 사항 — UI 조작 기준> |

## 이모지 요약 (1줄 질답·진행 중 간단 알림 전용 — 세션 종료 계열 보고 사용 금지)

> **사용 제한 (강제)**: 본 이모지 요약 형식은 "1줄 질답·진행 중 간단 알림"에만 사용. 세션 종료 계열 보고(완료·단계 완료·중단·보류)는 반드시 위 7개 표 형식으로만 작성 — 본 이모지 형식 사용 시 규칙 위반.

```
## 세션 완료 보고: <세션 한글명>

한 줄 요약: <이번 작업으로 무엇이 달라졌는가 — 사용자 관점 1문장>

💡 변경내용: <사용자가 확인할 수 있는 변화를 일반 사용자 용어로. 없으면 "화면 변화 없음(내부 개선)">

✅ 원칙: <원칙 전체 판정 결과와 근거. 하나라도 ❌/보류이면 완료 보고가 아니라 중단·보류 보고>

⚠️ 경고: <작업 중 발견한 오류·위험·잠재 버그. 없으면 "없음">

📦 커밋: <완료 여부·사용자용 요약> (변경 커밋 시) / 없음(변경 없음)
🚀 푸시: 안 함(기본) / 완료(사용자가 명시 요청 시)
📝 HANDOVER: 완료(<내용 요약 1줄>) / 보류(<사유>) / 갱신 없음(코드 수정 없음)
(위 3항목은 반드시 각각 독립된 줄로 표시. 통합·간접 표현 금지)

상태: <작업 완료 / 단계 완료·대기 / 중단·보류>
사용자 결정: <작업 완료·단계 완료 시 "없음(작업 종료)" / 중단·보류 시 재개에 필요한 결정>
사용자 확인: <항목 또는 없음>
```

> `작업 완료` 또는 `단계 완료·대기`인 경우 위 내용이 마지막입니다. 다음 단계 질문·승인 요청·추가 작업 권유를 붙이지 않습니다.
