# 태스크: 페이지별 구독 대상 사전 갱신 — 2세션 백엔드 전달·재연결

- **문서 역할**: 구현 방법과 완료 조건 정의
- **세션**: 2/4
- **상태**: 1세션 완료 후 구현 대기
- **선행 조건**: 1세션의 대상 저장소와 갱신 함수가 완료되어야 한다.
- **다음 세션**: 프론트엔드 페이지 이름 전용 구독 전환

## 1. 작업 목표

프론트엔드가 종목 코드 목록을 보내지 않아도, 백엔드가 저장된 최신 페이지 대상 목록을 사용해 구독 등록과 초기 스냅샷 전송을 수행한다.

## 1.1 원칙 준수 기준

- **P10 단일 소스**: 초기 스냅샷과 변경분은 같은 서버 대상 상태와 마스터 자료에서 만든다.
- **P11 폴링 금지**: 페이지 활성화·원본 변경·재연결 이벤트에만 전달 작업을 실행한다.
- **P24 단순성**: 추가·제거·초기 전송을 공통 연결 갱신 경로로 처리하고 페이지별 중복 전송 코드를 만들지 않는다.

## 2. 페이지 활성화 계약

- [ ] 프론트엔드가 페이지 이름만 보내는 활성화 메시지를 허용한다.
- [ ] 다음 여덟 페이지는 코드 목록 없이 활성화할 수 있어야 한다.
  - [ ] 업종 순위
  - [ ] 매수 후보
  - [ ] 보유 종목
  - [ ] 수익 현황
  - [ ] 수익 상세
  - [ ] 종목 분류
  - [ ] 종목 상세
  - [ ] 일반 설정
- [ ] 업종 순위·매수 후보·보유 종목·수익 현황은 서버가 대상 코드로 종목 실시간 구독을 처리한다.
- [ ] 수익 상세·종목 분류·종목 상세·일반 설정은 서버가 화면 자료의 초기 스냅샷과 변경 알림을 처리한다. 증권사 종목 실시간 구독은 만들지 않는다.
- [ ] 코드 목록이 명시된 기존 메시지는 전환 기간 동안 호환하되, 여덟 페이지의 새 프론트엔드는 코드 목록을 보내지 않는다.
- [ ] 지원하지 않는 페이지 이름은 기존 처리 규칙을 유지한다.
- [ ] 활성화 시 대상 저장소가 준비되지 않았으면 빈 스냅샷을 정상 데이터처럼 보내지 않는다.
- [ ] 대상 저장소가 준비된 뒤 새 페이지가 활성화되면 현재 대상 전체를 즉시 전송한다.

## 3. 연결별 구독 상태

- [ ] 연결별로 현재 활성 페이지와 현재 구독 코드 집합을 분리해 관리한다.
- [ ] 새 페이지 활성화 시 이전 페이지의 연결별 종목 구독을 제거한다.
- [ ] 새 대상의 추가 종목은 연결에 등록한다.
- [ ] 제거된 종목은 연결에서 해제한다.
- [ ] 같은 종목을 다른 연결이 이미 사용 중이어도 새 연결에는 초기 스냅샷을 보내야 한다.
- [ ] 전역 실시간 전송 시작 여부와 특정 브라우저 연결에 초기 스냅샷을 보낼지 여부를 분리한다. 한 연결의 초기 스냅샷이 다른 연결의 구독 여부에 의해 누락되면 안 된다.
- [ ] 대상 목록이 비어 있는 것이 정상인 경우에는 연결의 기존 구독을 정리하고 빈 상태를 명확히 표시한다.

## 4. 화면 유형별 초기 스냅샷

| 화면 유형 | 초기 전송 자료 | 이후 전송 |
|---|---|---|
| 종목 실시간 화면 | 대상 종목의 확정 데이터와 최신 시세 | 종목별 변경분 |
| 수익 상세 | 매수·매도 이력과 최신 변경 번호 | 이력 추가·변경 알림 |
| 종목 분류 | 분류 정의·업종 목록·분류 대상 | 분류 변경 알림 |
| 종목 상세 | 최신 5일 일봉 자료 | 장 마감 확정 자료 갱신 알림 또는 새 스냅샷 |
| 일반 설정 | 민감 정보가 가려진 최신 설정 | 설정 변경 알림 |

- [ ] 화면 자료의 초기 전송과 이후 변경 알림을 같은 페이지 활성화 계약으로 제공한다.
- [ ] 자료 유형이 다른 화면에 종목 실시간 구독을 억지로 붙이지 않는다.

## 5. 종목 실시간 초기 스냅샷

- [ ] 초기 스냅샷은 현재 대상 전체를 한 번 전송한다.
- [ ] 스냅샷에는 현재 화면에 필요한 확정 데이터와 최신 실시간 캐시 값을 모두 포함한다.
  - [ ] 종목명
  - [ ] 업종
  - [ ] 시장 구분
  - [ ] NXT 여부
  - [ ] 5일 평균 거래대금
  - [ ] 5일 최고가
  - [ ] 현재가·등락·등락률·당일 거래대금·체결강도
  - [ ] 호가 잔량·프로그램 순매수·뉴스 관련 값
- [ ] 5일 평균 거래대금은 기존 백만원 단위를 유지한다.
- [ ] 초기 스냅샷 이후에는 변경된 값만 기존 실시간 경로로 전달한다.
- [ ] 초기 스냅샷과 변경분의 데이터 계약을 동일하게 유지한다.

## 6. 원본 변경 시 활성 연결 갱신

1세션에서 갱신된 대상 목록을 모든 활성 연결에 반영한다.

- [ ] 설정 변경 후 업종 필터 대상이 바뀌면 업종 순위 연결의 구독을 갱신한다.
- [ ] 장 마감 확정 데이터 반영 후 대상이 바뀌면 업종 순위 연결의 구독을 갱신한다.
- [ ] 시장 시간대 변경 시 페이지별 대상 정책에 따라 구독을 갱신한다.
- [ ] 매수 후보 변경 시 매수 후보 연결을 갱신한다.
- [ ] 보유 종목 변경 시 보유 종목·수익 현황 연결을 함께 갱신한다.
- [ ] 대상 변경이 없으면 구독 해지·재등록과 초기 스냅샷을 반복하지 않는다.
- [ ] 추가 종목에는 초기 스냅샷을 보내고, 유지 종목에는 불필요한 전체 스냅샷을 반복하지 않는다.
- [ ] 제거 종목에는 더 이상 실시간 변경분을 보내지 않는다.
- [ ] 갱신 작업은 기존 이벤트 호출 체인에 연결한다. 타이머나 주기적 확인 루프를 새로 만들지 않는다.
- [ ] 갱신 작업 실패 시 다른 페이지와 다른 연결의 전송을 중단하지 않는다. 실패한 대상에 오류를 기록하고 다음 변경 이벤트에서 재시도 가능한 상태를 남긴다.

## 7. WebSocket 재연결

- [ ] 프론트엔드는 재연결 시 페이지 이름만 다시 보낸다.
- [ ] 백엔드는 저장된 최신 대상 목록을 사용해 해당 연결의 구독을 복원한다.
- [ ] 재연결 후 대상 전체의 초기 스냅샷을 다시 보내 로컬 상태를 복구한다.
- [ ] 연결이 끊긴 동안 바뀐 대상 목록은 재연결 시 최신 저장 결과를 사용한다.
- [ ] 이전 연결의 구독 코드가 새 연결에 남지 않는다.
- [ ] 재연결과 페이지 전환이 겹쳐도 대상 등록·해지가 뒤섞이지 않도록 기존 비동기 직렬화 방식을 사용한다.

## 8. 테스트 요구사항

- [ ] 코드 없이 종목 실시간 네 페이지를 활성화했을 때 저장된 대상이 등록되는지 테스트한다.
- [ ] 코드 없이 자료 중심 네 페이지를 활성화했을 때 해당 자료 스냅샷이 전송되는지 테스트한다.
- [ ] 새 연결이 이미 다른 연결이 구독 중인 종목을 요청해도 초기 스냅샷을 받는지 테스트한다.
- [ ] 대상 추가·제거 시 연결별 등록·해지가 정확한지 테스트한다.
- [ ] 대상 변경이 없을 때 중복 스냅샷이 발생하지 않는지 테스트한다.
- [ ] 설정 변경·후보 변경·보유 변경·장 마감 갱신 후 활성 연결이 갱신되는지 테스트한다.
- [ ] 페이지 비활성화와 연결 해제 시 구독이 정리되는지 테스트한다.
- [ ] 재연결 시 페이지 이름만으로 최신 대상이 복구되는지 테스트한다.
- [ ] 초기 스냅샷에 5일 평균 거래대금 등 확정 데이터가 포함되는지 테스트한다.
- [ ] 수익 상세 활성화 시 이력 초기 스냅샷이 전송되는지 테스트한다.
- [ ] 종목 분류 활성화 시 분류 초기 스냅샷이 전송되는지 테스트한다.
- [ ] 종목 상세 활성화 시 5일 일봉 초기 스냅샷이 전송되는지 테스트한다.
- [ ] 일반 설정 활성화 시 민감 정보가 가려진 설정 초기 스냅샷이 전송되는지 테스트한다.

## 9. 완료 기준

- [ ] 여덟 페이지 모두 코드 목록 없이 페이지 이름만으로 초기 자료를 받는다.
- [ ] 종목 실시간 구독이 필요한 네 화면과 자료 스냅샷만 필요한 네 화면의 전달 방식이 구분된다.
- [ ] 연결별 구독 상태와 서버 전체 실시간 구독 상태가 서로 영향을 주지 않는다.
- [ ] 원본 변경 시 활성 연결의 대상이 자동으로 최신화된다.
- [ ] 재연결 시 최신 대상과 초기 스냅샷이 복구된다.
- [ ] 대상 변경이 없을 때 중복 전송이 없다.
- [ ] 폴링이 추가되지 않는다.
- [ ] 백엔드 관련 테스트·린트·런타임 검증이 통과한다.

## 10. 범위 밖

- 프론트엔드 페이지 코드 목록 제거
- 화면 렌더링·표시 문구 변경
- 네 화면의 일반 조회를 제거하는 프론트엔드 작업
- 증권사 자체 실시간 등록 기준 변경
- 매매 판단·주문 실행·매도 조건 변경
