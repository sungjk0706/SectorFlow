# 태스크: 페이지별 구독 대상 사전 갱신 — 3세션 프론트엔드 전환

- **문서 역할**: 구현 방법과 완료 조건 정의
- **세션**: 3/4
- **상태**: 2세션 완료 후 구현 대기
- **선행 조건**: 백엔드가 코드 없는 페이지 활성화와 대상별 초기 스냅샷을 지원해야 한다.
- **다음 세션**: 통합 검증과 사용자 화면 확인

## 1. 작업 목표

여덟 페이지가 종목 코드 목록이나 화면별 세부 대상을 직접 보내지 않고 페이지 이름만 보내도록 전환한다. 일반 조회를 제거할지 여부는 화면 자료의 성격에 따라 백엔드 스냅샷 계약이 준비된 경우에만 제거한다.

## 1.1 원칙 준수 기준

- **P10 단일 소스**: 프론트엔드는 구독 대상 코드를 별도로 저장하지 않고 서버가 보낸 초기 자료와 변경분만 반영한다.
- **P11 폴링 금지**: 페이지 이동·재연결·서버 이벤트 기반으로만 화면을 갱신한다.
- **P24 단순성**: 여덟 페이지에서 같은 대상 수집·재구독 코드를 제거하고 공통 페이지 활성화 흐름을 사용한다.

## 2. 대상 페이지와 자료 유형

| 페이지 | 프론트엔드가 보내는 것 | 서버가 보내는 것 |
|---|---|---|
| 업종 순위 | 페이지 이름 | 필터 통과 종목 초기 스냅샷·업종 점수·실시간 변경분 |
| 매수 후보 | 페이지 이름 | 현재 후보 대상 초기 스냅샷·후보 자료·변경분 |
| 보유 종목 | 페이지 이름 | 현재 보유 대상 초기 스냅샷·계좌 변경분 |
| 수익 현황 | 페이지 이름 | 보유 대상 초기 스냅샷·계좌 요약 변경분 |
| 수익 상세 | 페이지 이름 | 매수·매도 이력 초기 스냅샷·이력 변경분 |
| 종목 분류 | 페이지 이름 | 분류 정의·업종·전체 분류 대상 초기 스냅샷·변경분 |
| 종목 상세 | 페이지 이름 | 최신 5일 일봉 초기 스냅샷·확정 자료 갱신분 |
| 일반 설정 | 페이지 이름 | 마스킹된 설정 초기 스냅샷·설정 변경분 |

## 3. 공통 WebSocket 전환

- [ ] 페이지 활성화 메시지에서 종목 코드 목록을 제거한다.
- [ ] 페이지 이름만 보내는 공통 호출을 사용한다.
- [ ] WebSocket 재연결 시 현재 페이지 이름만 다시 보낸다.
- [ ] 현재 페이지 코드 목록을 별도로 보관하거나 복원하지 않는다.
- [ ] 페이지 비활성화 시 기존 정리 메시지는 유지한다.
- [ ] 다른 종류의 구독 정보(필드 선택 등)는 이번 범위에서 임의로 제거하지 않는다.

## 4. 업종 순위 화면

- [ ] 이미 적용된 서버 주도 초기 대상 선정을 유지한다.
- [ ] 화면 진입 시 별도 종목 목록·업종 점수 일반 조회를 다시 추가하지 않는다.
- [ ] 초기에는 빈 상태 또는 수신 대기 상태를 표시한다.
- [ ] 초기 스냅샷 도착 후 종목 행과 요약 정보를 표시한다.
- [ ] 업종 점수 실시간 이벤트 도착 후 가운데 순위와 종목 행 순서를 갱신한다.
- [ ] 5일 평균 거래대금·종목명·업종·시장 정보가 초기 스냅샷으로 표시되는지 확인한다.
- [ ] 초기 데이터 도착 전 가상 스크롤이 행을 겹치게 만들지 않는지 확인한다.
- [ ] 초기 스냅샷 도착 전 store 변경 감시가 연결되어 있어 데이터를 놓치지 않는지 확인한다.

## 5. 매수 후보 화면

- [ ] 계좌·보유·매수 후보 화면 데이터 조회는 기존 정책을 유지한다.
- [ ] 매수 후보 코드 목록을 프론트엔드에서 다시 만들어 구독 메시지에 넣지 않는다.
- [ ] 매수 후보 목록이 바뀔 때 직접 코드 목록을 다시 보내는 로직을 제거한다.
- [ ] 서버가 새 후보와 제거 후보를 반영한 뒤 초기 스냅샷·변경분을 보낸다.
- [ ] 매수 후보 표의 행 데이터와 masterStocks 실시간 표시가 모두 정상 갱신되는지 확인한다.
- [ ] 매수 후보가 없는 상태에서도 서버 구독 해지와 빈 화면 표시가 정상인지 확인한다.
- [ ] 매수 가능 수량 계산이 실시간 masterStocks의 현재가를 계속 사용하는지 확인한다.

## 6. 보유 종목 화면

- [ ] 계좌·보유 목록 일반 조회는 기존 정책을 유지한다.
- [ ] 보유 종목 코드 목록을 프론트엔드에서 구독 메시지에 넣지 않는다.
- [ ] 신규 매수·부분 매도·전량 매도 후 프론트엔드가 직접 재구독하지 않는다.
- [ ] 서버가 보유 목록 변경을 감지해 구독 대상과 초기 스냅샷을 갱신한다.
- [ ] 보유 종목이 없는 상태에서 기존 구독이 정리되는지 확인한다.
- [ ] 현재가·평가손익·수익률 표시가 기존과 동일한 원본을 사용하는지 확인한다.
- [ ] 보유 종목 행이 초기 스냅샷 도착 전 잘못된 이전 종목을 표시하지 않는지 확인한다.

## 7. 수익 현황 화면

- [ ] 계좌·보유 목록 일반 조회는 기존 정책을 유지한다.
- [ ] 보유 종목 코드를 구독 메시지에 넣지 않는다.
- [ ] 보유 종목 대상은 보유 종목 화면과 같은 서버 대상 집합을 사용한다.
- [ ] 신규 매수·부분 매도·전량 매도 후 서버 갱신이 수익 현황에도 적용되는지 확인한다.
- [ ] 계좌 요약 이벤트와 종목 실시간 이벤트가 서로 섞이지 않도록 기존 이벤트 역할을 유지한다.

## 8. 수익 상세 화면

- [ ] 페이지 진입 시 매수·매도 이력 일반 조회를 중복 호출하지 않고 서버 초기 스냅샷을 사용한다.
- [ ] 이력 추가·변경 알림을 기존 이력 저장소에 반영한다.
- [ ] 종목 실시간 구독은 신청하지 않는다.
- [ ] 이력 표의 종목명·시장 표시가 초기 자료와 기존 기록 자료로 정상 표시된다.

## 9. 종목 분류 화면

- [ ] 페이지 진입 시 분류 정의와 전체 분류 대상 일반 조회를 중복 호출하지 않고 서버 초기 스냅샷을 사용한다.
- [ ] 분류 변경 알림을 분류 저장소에 반영한다.
- [ ] 종목 실시간 구독은 신청하지 않는다.
- [ ] 분류 편집·검색·업종 이동 기능은 기존 동작을 유지한다.

## 10. 종목 상세 화면

- [ ] 페이지 진입 시 5일 일봉 일반 조회를 중복 호출하지 않고 서버 초기 스냅샷을 사용한다.
- [ ] 장 마감 확정 자료 갱신 시 서버가 새 스냅샷 또는 갱신 알림을 보낸다.
- [ ] 종목 실시간 구독은 신청하지 않는다.
- [ ] 날짜별 컬럼 생성·검색·요약 표시를 기존과 동일하게 유지한다.

## 11. 일반 설정 화면

- [ ] 페이지 진입 시 설정 일반 조회를 중복 호출하지 않고 서버 초기 스냅샷을 사용한다.
- [ ] 민감한 설정값은 기존과 같은 마스킹 상태로만 받는다.
- [ ] 설정 변경 알림을 설정 저장소와 화면에 반영한다.
- [ ] 종목 실시간 구독은 신청하지 않는다.

## 12. 프론트 상태·렌더링 검증

- [ ] 초기 스냅샷이 store에 병합될 때 기존 다른 종목을 불필요하게 지우지 않는다.
- [ ] 페이지 전환 시 이전 페이지 종목이 다음 페이지 화면에 남지 않는다.
- [ ] 재연결 후 초기 스냅샷이 도착하면 화면이 다시 채워진다.
- [ ] 실시간 변경분은 현재가·등락·체결강도·당일 거래대금 등 기존 화면과 같은 방식으로 반영된다.
- [ ] 확정 데이터는 실시간 틱마다 불필요하게 덮어쓰지 않는다.
- [ ] 수신 대기·데이터 없음·구독 실패를 구분해 화면에 표시한다.
- [ ] 빈 목록을 정상 데이터로 오인해 기존 정상 데이터가 사라지지 않는다.

## 13. 테스트 요구사항

- [ ] 여덟 페이지가 페이지 이름만 보내는지 테스트한다.
- [ ] 재연결 시 코드 목록 없이 페이지 이름만 재전송하는지 테스트한다.
- [ ] 후보·보유 목록 변경 시 프론트엔드가 직접 종목 코드를 보내지 않는지 테스트한다.
- [ ] 초기 스냅샷 수신 후 masterStocks가 화면에 반영되는지 테스트한다.
- [ ] 초기 스냅샷과 실시간 변경분의 순서가 바뀌어도 최신 값이 유지되는지 기존 freshness 규칙으로 확인한다.
- [ ] 업종 순위 가상 스크롤 초기 렌더와 이후 데이터 도착 렌더를 테스트한다.
- [ ] 수익 상세·종목 분류·종목 상세·일반 설정이 각각 종목 코드 구독 없이 초기 자료를 표시하는지 테스트한다.
- [ ] 관련 화면 테스트·타입 검사·린트를 통과한다.

## 14. 완료 기준

- [ ] 여덟 페이지의 페이지 활성화 요청에는 페이지 이름만 포함된다.
- [ ] 종목 실시간 구독이 필요한 네 화면에도 종목 코드 목록이 포함되지 않는다.
- [ ] 프론트엔드에 페이지별 구독 대상 코드 관리가 남아 있지 않다.
- [ ] 서버 초기 스냅샷 도착 후 네 화면이 기존과 같은 정보를 표시한다.
- [ ] 계좌·후보·보유 일반 조회 등 범위 밖 기능은 변경되지 않는다.
- [ ] 재연결·페이지 전환·빈 목록·후보/보유 변화가 정상 동작한다.
- [ ] 프론트엔드 전체 테스트·타입 검사·린트·빌드가 통과한다.

- 백엔드 WebSocket 전송·재연결 구현
- 매매 판단·주문·리스크 계산 변경
- 일반 조회 자체의 제거 또는 변경
